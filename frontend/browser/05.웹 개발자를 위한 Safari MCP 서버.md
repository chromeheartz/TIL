# 웹 개발자를 위한 Safari MCP 서버

> **원문**: [Introducing the Safari MCP Server for web developers](https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/) — Saron Yitbarek, Jen Simmons, Jon Davis (WebKit Blog, 2026.07.01)
> **번역 출처**: [(번역) 웹 개발자를 위한 Safari MCP 서버를 소개합니다](https://emewjin.github.io/introduce-safari-mcp/) — emewjin

Safari 호환성 이슈 잡을 때마다 맥북 열고 Safari 띄우고 개발자 도구 켜고… 이 왕복이 늘 귀찮았다. 그런데 애플이 `safaridriver`에 MCP 모드를 넣었다길래 정리해둔다. 터미널 안에서 에이전트가 직접 Safari를 열고 확인해준다는 얘기다.

Safari 27과 Safari Technology Preview 247부터 제공된다.

### 뭐 하는 물건인가

한 줄로 요약하면 **AI 에이전트를 실제 Safari 렌더링 엔진에 연결해주는 MCP 서버**다.

에이전트가 코드만 보고 "아마 이래서 깨질 겁니다"라고 추측하는 게 아니라, 진짜 Safari에서 페이지를 열어보고 DOM을 읽고 콘솔 로그를 확인하고 스크린샷을 찍어서 판단한다. 별도 앱을 깔 필요도 없다 — 이미 macOS에 들어있는 `safaridriver` 바이너리에 `--mcp` 플래그를 붙이면 끝이다.

### 어디에 쓰나

원문이 든 사용 사례는 다섯 가지.

- **Safari에서 개발하기** — 만든 걸 Safari 기준으로 바로바로 검증
- **Safari 호환성 개선** — 크롬에선 되는데 사파리에서 깨지는 그것
- **성능 분석** — navigation timing, 리소스 로드 시간 확인
- **접근성 확인** — 라벨, ARIA 속성, 색상 대비 점검
- **사용자 상태 검증** — 폼 상태, 요소 쿼리, 인터랙션이 실제로 동작하는지

특히 두 번째가 제일 와닿는다. Safari 전용 버그는 재현 → 확인 → 수정 → 재확인 루프가 유난히 길었는데, 그 루프를 터미널 밖으로 나가지 않고 돌릴 수 있게 된다.

### 제공하는 도구 17개

| 도구 | 하는 일 |
|---|---|
| `list_tabs` | 열려있는 탭 전체 나열 (핸들, URL) |
| `create_tab` | 새 탭 생성 (URL 지정 가능) |
| `switch_tab` | 다른 탭으로 전환 |
| `close_tab` | 탭 닫기 |
| `navigate_to_url` | URL 이동 후 로드된 페이지 콘텐츠 반환 |
| `wait_for_navigation` | 로딩 완료까지 대기, 최종 URL·제목 반환 |
| `page_info` | 현재 페이지 정보 (URL, 제목, 로딩 상태) |
| `get_page_content` | 페이지 텍스트 추출 (마크다운/HTML/JSON 등 포맷 선택) |
| `page_interactions` | DOM 조작 — 클릭, 입력, 스크롤, 호버, 키 입력 |
| `evaluate_javascript` | 페이지 컨텍스트에서 JS 실행하고 결과 반환 |
| `screenshot` | 현재 페이지 스크린샷 (PNG) |
| `browser_console_messages` | 버퍼링된 콘솔 로그 반환 |
| `browser_dialogs` | 다이얼로그 나열 및 응답 (수락/거절/텍스트 입력) |
| `list_network_requests` | 네트워크 요청 요약 (URL, 메서드, 상태, 타이밍) |
| `get_network_request` | 특정 요청의 전체 상세 (헤더, 본문, 타이밍) |
| `set_viewport_size` | 뷰포트 크기 설정 (CSS 픽셀) |
| `set_emulated_media` | CSS 미디어 타입 에뮬레이션 |

눈여겨볼 건 `browser_dialogs`. `alert`/`confirm` 같은 모달이 뜨면 보통 자동화가 그대로 멈춰버리는데, 이걸 에이전트가 처리할 수 있게 열어뒀다. 그리고 `set_emulated_media`는 반응형·다크모드·프린트 스타일 확인용으로 꽤 유용할 듯.

### 📌 1단계: Safari 설정 켜기

먼저 Safari Technology Preview를 설치한다(Safari 27이면 그대로 써도 된다). 그다음 설정 두 개를 켜야 한다.

```
Safari Settings > Advanced > "Show features for web developers" 체크
Safari Settings > Developer > "Enable remote automation and external agents" 체크
```

두 번째 항목은 첫 번째를 켜야 나타난다. 순서 주의.

### 📌 2단계: MCP 서버 등록

**Claude Code**

```bash
# Safari Technology Preview
claude mcp add safari-mcp-stp -- "/Applications/Safari Technology Preview.app/Contents/MacOS/safaridriver" --mcp

# Safari 27 (정식)
claude mcp add safari-mcp -- "/usr/bin/safaridriver" --mcp
```

**Codex**

```bash
# Safari Technology Preview
codex mcp add safari-mcp-stp -- "/Applications/Safari Technology Preview.app/Contents/MacOS/safaridriver" --mcp

# Safari 27 (정식)
codex mcp add safari-mcp -- "/usr/bin/safaridriver" --mcp
```

**그 외 MCP 클라이언트** — 설정 JSON에 직접 추가한다.

```json
// Safari Technology Preview
"safari-mcp-stp": {
  "command": "/Applications/Safari Technology Preview.app/Contents/MacOS/safaridriver",
  "args": ["--mcp"]
}

// Safari 27 (정식)
"safari-mcp": {
  "command": "/usr/bin/safaridriver",
  "args": ["--mcp"]
}
```

정식 Safari는 경로가 `/usr/bin/safaridriver`로 짧다. STP는 앱 번들 안쪽 경로라 공백이 들어가니 **따옴표를 반드시 감싼다.**

### 📌 3단계: 던져볼 프롬프트

원문이 예시로 준 첫 프롬프트들.

```
Find bugs on my site in Safari
How accessible is my site in Safari?
See how my website performs in Safari
```

특별한 문법이 없다. 그냥 "사파리에서 확인해줘"라고 하면 에이전트가 알아서 탭 열고 스크린샷 찍고 콘솔 뒤진다.

### 보안·개인정보

이 부분이 꽤 명확하게 선을 그어놨다.

- ✅ **전부 로컬에서 실행된다** — 외부 네트워크 호출 없음
- ✅ **Safari의 개인정보에는 접근 불가** — AutoFill 데이터, 브라우징 기록 못 읽는다
- ✅ **페이지 콘텐츠·스크린샷·콘솔 로그는 에이전트에만 직접 전달** — Apple로 가지 않는다
- ⚠️ 다만 **그 이후는 내가 쓰는 에이전트/모델 정책에 달렸다**

마지막 줄이 핵심이다. Safari는 데이터를 안 가져가지만, 스크린샷을 받아든 에이전트가 그걸 어디로 보내는지는 별개 문제다. 사내 어드민이나 실 고객 데이터가 떠 있는 페이지에 붙일 땐 이걸 먼저 따져야 한다.

### 📌 정리

`safaridriver --mcp — 이미 깔려 있는 바이너리에 플래그 하나 붙이면 Safari가 에이전트에 연결된다`

#### 핵심

> Safari 27 / STP 247부터 `safaridriver`에 `--mcp` 플래그가 생겼다. 이걸 MCP 서버로 등록하면 에이전트가 실제 Safari에서 탭을 열고, DOM을 읽고, JS를 실행하고, 네트워크 요청과 콘솔 로그를 확인하고, 스크린샷을 찍을 수 있다. 도구는 17개. 전부 로컬에서 돌고 Apple로 데이터가 가지 않지만, 그다음 에이전트가 뭘 하는지는 별개다. 별도 설치물 없이 macOS 기본 바이너리를 그대로 쓴다는 게 제일 큰 장점.

#### ⭐️ 앞으로 기억할 것

- 1. 새로 설치할 게 없다
`safaridriver`는 이미 macOS에 있다. Playwright나 별도 드라이버 없이 `--mcp` 플래그만 붙이면 된다. Safari 27이면 경로도 그냥 `/usr/bin/safaridriver`.
```bash
claude mcp add safari-mcp -- "/usr/bin/safaridriver" --mcp
```

- 2. Safari 설정 두 개를 먼저 켜야 한다
이거 안 켜면 연결이 안 된다. 그리고 Developer 탭 자체가 Advanced 설정을 켜야 나타나므로 순서가 있다.
```
Advanced > Show features for web developers
  → Developer > Enable remote automation and external agents
```

- 3. STP 경로는 공백이 있으니 따옴표 필수
`/Applications/Safari Technology Preview.app/...` — "Safari Technology Preview"에 공백이 들어간다. 따옴표 안 감싸면 인자가 쪼개진다.

- 4. `browser_dialogs`가 있다는 걸 기억할 것
`alert`/`confirm`이 뜨면 보통 브라우저 자동화가 통째로 멈춘다. Safari MCP는 다이얼로그를 나열하고 응답할 수 있는 도구를 따로 제공한다 — 모달 있는 플로우도 자동화 가능하다는 뜻.

- 5. 데이터 경계는 Safari까지만이다
Safari는 개인정보를 안 넘기고 Apple로도 안 보낸다. 하지만 스크린샷·콘솔 로그를 받은 **에이전트**가 어디로 보내는지는 그 에이전트 정책. 민감한 화면에 붙이기 전에 확인.

> **📌 결론**
> ▎ Safari 27 / STP 247부터 `safaridriver --mcp`로 MCP 서버를 띄울 수 있다.
> ▎ 탭 관리·네비게이션·DOM 조작·JS 실행·네트워크·콘솔·스크린샷·뷰포트/미디어 에뮬레이션까지 17개 도구.
> ▎ 별도 설치물이 없다 — macOS 기본 바이너리 + 플래그 하나.
> ▎ 사전 조건은 Safari 설정 두 개(개발자 기능 표시 → 원격 자동화 허용), 순서 있음.
> ▎ 로컬 실행이고 Apple로 데이터가 가지 않지만, 이후 에이전트 처리 정책은 별개.
> ▎ ⭐️ 실무 적용 포인트: ① "크롬에선 되는데 사파리에서 깨짐" 티켓 잡을 때 재현→수정→재확인 루프를 터미널 안에서 끝낼 수 있다 ② `set_emulated_media` + `set_viewport_size`로 반응형·다크모드·프린트 스타일 회귀 확인 ③ 접근성 점검(라벨/ARIA/대비)을 PR 단계에 끼워넣기 ④ 사내 어드민처럼 실데이터 뜬 화면엔 붙이기 전에 데이터 정책 먼저 확인
