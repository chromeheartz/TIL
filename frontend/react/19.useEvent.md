# useEvent 리액트 훅이란 (또 무엇이 아닌지)

> **원문**: https://typeofnan.dev/what-the-useevent-react-hook-is-and-isnt/ (TypeOfNan)
> **번역 출처**: https://velog.io/@eunbinn/what-the-useevent-react-hook-is-and-isnt

리액트 쓰면서 "왜 이 컴포넌트가 자꾸 리렌더되지?", "의존성 배열에 이거 넣으면 effect가 너무 자주 도는데?" 하는 고질병이 있었다. 리액트 코어팀이 이걸 겨냥한 `useEvent` RFC를 냈길래 정리해둔다. (※ RFC 단계라 아직 못 쓰고, 이름·세부사항은 바뀔 수 있다. 실제로 이후 `useEffectEvent`로 이름이 바뀌어 실험 채널에 들어왔다.)

### 리액트는 "이전 값 vs 현재 값" 비교로 동작한다

리액트의 실행 모델은 기본적으로 현재 값과 이전 값을 비교하는 것이다. 컴포넌트 내부, 그리고 `useEffect`·`useMemo`·`useCallback` 같은 훅에서 이게 일어난다.

```javascript
function MyApp() {
  const [count, setCount] = useState(0);
  return <Counter count={count} />;
}
```

`count`가 바뀌면 `Counter`가 리렌더된다. count 변화에 맞춰 effect를 돌리려면:

```javascript
function MyApp() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log(count);
  }, [count]); // 의존성 배열에 있으니 count 바뀔 때마다 실행

  return <Counter count={count} />;
}
```

### 그래서 무엇이 문제인가

흔히 겪는 두 문제: **컴포넌트가 너무 자주 리렌더**되거나, **훅이 과도하게(때론 무한히) 재실행**된다.

**문제 1 — 매 입력마다 함수가 새로 만들어진다**

```javascript
function Chat() {
  const [text, setText] = useState("");

  const onClick = () => {
    sendMessage(text);
  };

  return <SendButton onClick={onClick} />;
}
```

`text`가 바뀔 때마다 `onClick`이 **새 함수**로 재생성된다. `SendButton`은 매 키 입력마다 다른 함수 참조를 받으니 불필요하게 리렌더된다.

**문제 2 — 의존성 때문에 effect가 원치 않게 실행된다** (Dan Abramov 트윗 예시)

```javascript
function Page({ route, currentUser }) {
  useEffect(() => {
    logAnalytics("visit_page", route.url, currentUser.name);
  }, [route.url, currentUser.name]);
}
```

문제: **유저 이름만 바뀌어도 페이지 방문 로그가 찍힌다**(원치 않음). `currentUser.name`을 의존성에서 빼면 되지 않냐고? 리액트는 그걸 권하지 않는다 — **stale closure(낡은 클로저)** 와 추적 버그를 만들기 때문. `react-hooks`의 `exhaustive-deps` ESLint 룰이 이걸 얼마나 중요하게 보는지를 보여준다.

### 제안된 해결책: useEvent

`useEvent`는 의존성에 따라 새 함수를 만들지 않고 **함수에 안정적인(stable) 참조**를 제공한다. 동시에 내부에서는 항상 **최신 값**을 읽는다.

**문제 1 해결:**

```javascript
function Chat() {
  const [text, setText] = useState("");

  const onClick = useEvent(() => {
    sendMessage(text);
  });

  return <SendButton onClick={onClick} />;
}
```

이제 `onClick`은 렌더 간 **같은 참조**를 유지 → `SendButton` 불필요 리렌더 방지. 그런데도 호출 시점의 최신 `text`를 읽는다.

**문제 2 해결:**

```javascript
function Page({ route, currentUser }) {
  const logVisit = useEvent((pageUrl) => {
    logAnalytics("visit_page", pageUrl, currentUser.name);
  });

  useEffect(() => {
    logVisit(route.url);
  }, [route.url]); // currentUser.name은 의존성에서 빠졌지만 최신값 사용
}
```

`logVisit`이 안정적이라 effect는 **`route.url`이 바뀔 때만** 실행되고, 그러면서도 최신 `currentUser.name`에 접근한다. (stale closure 없이!)

### useCallback과 뭐가 다른가

`useCallback`도 함수를 메모이즈하지만 **의존성이 바뀌면 새 함수를 만든다** → 의존성에 넣은 값이 자주 바뀌면 참조도 자주 바뀐다. 반대로 의존성에서 빼면 stale closure가 생긴다. `useEvent`는 **참조는 항상 고정 + 내부 값은 항상 최신**이라 이 딜레마 자체를 없앤다.

| | useCallback | useEvent |
|---|---|---|
| 참조 안정성 | 의존성 바뀌면 깨짐 | 항상 고정 |
| 내부 값 | 의존성에 따라(빼면 stale) | 항상 최신 |
| 용도 | 메모이즈된 콜백 | "이벤트성" 콜백(렌더 중 호출 X) |

### 첫인상 & 한계

- 이름이 헷갈린다는 게 저자(와 많은 사람)의 첫 반응. (그래서 이후 `useEffectEvent`로 변경됨)
- 만능이 아니다. 리액트에 "또 하나의 개념"을 추가하는 것.
- 근본적으로 **리액트는 여전히 비반응형(non-reactive)** 이다 — SolidJS 같은 진짜 반응형 프레임워크와 다르다.

**SolidJS 비교** — 의존성을 "자동으로" 추적하고, 제외하고 싶은 값만 `untrack`으로 감싼다:

```javascript
function Page(props) {
  createEffect(() => {
    logAnalytics(
      "visit_page",
      props.route.url,
      untrack(() => props.currentUser.name) // 이 값은 추적에서 제외
    );
  });
}
```

`props.route.url`이 바뀔 때 실행되지만, 의존성 명시 없이도 현재 유저 이름을 캡처한다. 리액트의 `useEvent`는 이 "자동 추적"을 수동 훅으로 흉내 내는 셈.

### 📌 정리
`useEvent = 참조는 고정, 내부 값은 항상 최신인 "이벤트성" 콜백`

#### 핵심
> 리액트는 이전/현재 값 비교로 동작해서, 콜백이 매 렌더 재생성되어 자식이 불필요하게 리렌더되거나, effect 의존성 때문에 원치 않게 재실행되는 문제가 있다. 의존성에서 빼면 stale closure가 생긴다. `useEvent`(현 `useEffectEvent`)는 **함수 참조를 항상 고정**하면서 **호출 시점의 최신 값**을 읽게 해 이 딜레마를 푼다. 단 만능은 아니고, 리액트가 SolidJS처럼 반응형이 되는 건 아니다.

#### ⭐️ 앞으로 기억할 것
- 1. 문제의 본질은 "참조 안정성 vs 최신 값" 딜레마
  useCallback은 둘을 동시에 못 잡는다(의존성 넣으면 참조 깨짐, 빼면 stale).
- 2. useEvent는 둘 다 잡는다
  참조 고정 + 항상 최신값. 자식 리렌더 방지 + effect 의존성 최소화.
  ```javascript
  const onClick = useEvent(() => sendMessage(text)); // 참조 고정, text는 최신
  ```
- 3. effect에서 "값은 쓰되 의존성엔 넣기 싫은" 것에 딱
  ```javascript
  const logVisit = useEvent((url) => logAnalytics(url, currentUser.name));
  useEffect(() => logVisit(route.url), [route.url]); // name은 최신, 의존성엔 없음
  ```
- 4. 렌더 중에는 호출하지 않는다
  "이벤트성" 콜백 — 이벤트 핸들러나 effect 안에서 호출하는 용도. 렌더링 도중 호출 금지.
- 5. 이름은 useEffectEvent로 바뀜
  원문은 RFC `useEvent` 기준. 현재는 `useEffectEvent`로 실험 채널 제공.

📌 결론
▎ "참조 고정 + 최신 값"을 동시에 주는 게 useEvent의 존재 이유.
▎ useCallback 의존성 지옥과 stale closure를 동시에 해결.
▎ 그래도 리액트는 비반응형 — SolidJS의 자동 추적/`untrack`과는 출발점이 다르다.
▎ ⭐️ 실무 적용 포인트
  - "이 effect가 X 바뀔 때만 돌면 좋겠는데 Y 값도 최신으로 써야 해" → useEffectEvent.
  - 자식에 내려주는 콜백이 부모 state 때문에 매번 새로 생겨 리렌더를 유발할 때.
  - 아직 실험 단계라 프로덕션 도입은 안정화 확인 후. exhaustive-deps 룰은 계속 존중.
