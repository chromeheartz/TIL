# Record & Tuple — 불변성을 가진 자바스크립트 자료구조

> **원문**: https://portal.gitnation.org/contents/record-and-tuple-immutable-data-structures-in-js (JSNation 2022, Robin Ricard)
> **번역 출처**: https://velog.io/@eunbinn/Record-Tuple-Immutable-Data-Structures-in-JS

객체 불변성을 지키려고 `Object.freeze`, `structuredClone`, `JSON.parse(JSON.stringify(...))` 같은 걸 써봤는데 다 불편하거나 함정이 있었다. Record & Tuple은 아예 **언어 차원에서 깊은 불변성 + 값 기반 동등성**을 가진 새 원시 타입을 추가하는 TC39 제안이다. `#{}` / `#[]` 문법이 처음엔 낯설지만 개념은 명확해서 정리해둔다.

## 1. 객체는 참조, 원시값은 값

### 원시값은 값을 담는다

```javascript
let proposalName = "Record & Tuple";
let proposalName2 = "Record & Tuple";
assert(proposalName === proposalName2); // OK ✅ (값 비교)
```

### 객체는 참조를 담는다

```javascript
let proposal = { name: "Record & Tuple" };
let proposal2 = { name: "Record & Tuple" };
assert(proposal === proposal2); // NOT OK 🛑 (내용 같아도 다른 참조)
```

내용이 같아도 각자 다른 메모리를 차지하므로 참조 비교에서 다르다.

### 원시값은 불변

```javascript
let proposalName = "Record & Tuple";
proposalName[10] = "o"; // 🛑 TypeError (strict mode)
assert(proposalName === "Record & Tople"); // NOT OK 🛑
```

### 객체는 가변 (const여도)

```javascript
const proposal = { name: "Record & Tuple" };
proposal.name = "Record & Toople";
assert(proposal.name === "Record & Toople"); // OK ✅
```

`const`는 재할당만 막을 뿐, 속성 변경은 막지 못한다.

### freeze 해도 얕다(shallow)

```javascript
const proposal = {
  name: "Record & Tuple",
  championGroup: ["Robin", "Rick", "Dan", "Nicolo"],
};
Object.freeze(proposal);
proposal.name = "Record & Toople"; // 🛑 TypeError

// 하지만 중첩 배열은 여전히 변경 가능
proposal.championGroup.push("Ashley");
assert(proposal.championGroup.length === 5); // OK ✅ (freeze가 깊지 않음)
```

## 2. 객체 불변성의 두 가지 문제

### 문제 1 — const + freeze로도 중첩 값을 보장 못 한다

```javascript
const config = {
  db: { host: "pg0" /* ... */ },
};

Object.freeze(config);
await initConnections(config); // 💥 initConnections가 config.db를 안 바꾼다고 믿을 수 있나?
assert(config.db.host === "pg0"); // 🛑 바뀌었을 수도 있다
```

중첩 객체는 freeze해도 가변이라, 함수에 넘기면 내부가 바뀔 위험이 있다. 방어하려면 깊은 복사가 필요한데 비용이 든다.

```javascript
await initConnections(JSON.parse(JSON.stringify(config))); // 변경 방지용 복사 (성능 저하)
```

> `JSON.parse(JSON.stringify())`는 느리다. 요즘은 `structuredClone()`을 쓰는 게 낫다 — 그래도 매번 복사해야 하는 건 마찬가지.

### 문제 2 — Map 키는 정확한 참조를 요구한다

```javascript
const boaty = { name: "Boaty McBoatface" };
const coords = { lat: 13, lon: -24 };
const boats = new Map([[coords, boaty] /* ... */]);

assert(boats.get(coords) === boaty); // OK ✅

const coordsCopy = { ...coords };
assert(boats.get(coordsCopy) === boaty); // NOT OK 🛑 (값은 같지만 다른 참조)
```

해결하려고 키를 문자열로 직렬화하면 또 함정:
- 키 순서에 민감: `'{"lat":13,"lon":-24}' !== '{"lon":-24,"lat":13}'`
- 순환 참조나 직렬화 불가 객체/함수는 처리 못 함

## 3. Record & Tuple (TC39 Stage 2)

### 문법 — `#{}` 와 `#[]`

```javascript
const record = #{
  name: "Record & Tuple",
  stage: 2,
};

const tuple = #["Record & Tuple", 2];
```

서로 중첩 가능:

```javascript
// Tuple 안에 Record
const proposals = #[
  #{ name: "Record & Tuple", stage: 2 },
  #{ name: "Change Array by Copy", stage: 3 },
  #{ name: "Symbols as WeakMap keys", stage: 3 },
];

// Record 안에 Tuple
const rt = #{ championGroup: #["Robin", "Rick", "Dan", "Nicolo", "Ashley"] };
```

### 불변성 — freeze 필요 없음

```javascript
const record = #{ name: "Record & Tuple", stage: 2 };
record.name = "Record & Toople"; // TypeError 🛑
```

### 깊은 불변성 (재귀적)

```javascript
const proposals = #[
  #{ name: "Record & Tuple", stage: 2 },
  // ...
];
proposals[0].name = "Record & Toople"; // TypeError 🛑 (중첩도 불변)
```

### 값 기반 동등성 (핵심!)

```javascript
// 객체: 참조 비교
assert([1, 2, 3] === [1, 2, 3]); // NOT OK 🛑
assert({ a: 1 } === { a: 1 }); // NOT OK 🛑

// Record & Tuple: 값 비교
assert(#{ a: 1 } === #{ a: 1 }); // OK ✅
assert(#[1, 2, 3] === #[1, 2, 3]); // OK ✅
```

### 원시 타입이다

```javascript
assert(typeof #{ a: 1 } === "record"); // OK ✅
assert(typeof #[1, 2, 3] === "tuple"); // OK ✅
```

`typeof`가 `"object"`가 아니라 `"record"` / `"tuple"`을 반환한다.

### 앞의 문제들이 풀린다

**문제 1 해결** — freeze 없이 완전 불변:

```javascript
const config = #{
  db: #{ host: "pg0" /* ... */ },
};
await initConnections(config);
assert(config.db.host === "pg0"); // OK ✅ (바꾸려 하면 즉시 에러)
```

**문제 2 해결** — 값 기반이라 복사해도 Map 키가 매칭:

```javascript
const boaty = { name: "Boaty McBoatface" };
const coords = #{ lat: 13, lon: -24 };
const boats = new Map([[coords, boaty]]);
assert(boats.get(coords) === boaty); // OK ✅

const coordsCopy = #{ ...coords };
assert(boats.get(coordsCopy) === boaty); // OK ✅
```

**키 순서 무관**:

```javascript
const coords1 = #{ lat: 13, lon: -24 };
const coords2 = #{ lon: -24, lat: 13 };
assert(coords1 === coords2); // OK ✅

Object.keys(coords1); // ["lat", "lon"]
Object.keys(coords2); // ["lat", "lon"] (사전순으로 정규화됨)
```

### 제약 — 객체/함수를 담을 수 없다

```javascript
const config = #{
  db: { host: "pg0" }, // 🛑 TypeError (#{} 아닌 일반 객체)
};

const config2 = #{
  db: #{
    host: "pg0",
    onConnect: () => {}, // 🛑 TypeError (함수도 객체라 불가)
  },
};
```

Record/Tuple 안에는 원시값과 다른 Record/Tuple만 담을 수 있다. (우회법은 있지만 범위 밖)

### 값 업데이트 — 스프레드 + 비변경 메서드

```javascript
const champions = #["Robin", "Rick", "Dan"];
champions.push("Nicolo", "Ashley"); // 🛑 push is not a function

// 스프레드로 새 Tuple 생성
const stage1And2 = #["Robin", "Rick", "Dan"];
const stage3 = #["Nicolo", "Ashley"];
const all = #[...stage1And2, ...stage3];
assert(all === #["Robin", "Rick", "Dan", "Nicolo", "Ashley"]); // OK ✅

// Record도 스프레드 + 오버라이드
const proposal = #{ name: "Record & Tuple", stage: 2 };
const proposalSoon = #{ ...proposal, stage: 3 };
assert(proposalSoon === #{ name: "Record & Tuple", stage: 3 }); // OK ✅
```

변경 메서드 대신 복사본 반환 메서드를 쓴다 (ES2023의 그 메서드들과 동일 컨셉):

- `.toReversed()` — `.reverse()`의 불변 버전
- `.toSorted([fn])` — `.sort()`의 불변 버전
- `.with(i, v)` — `arr[i] = v`의 불변 버전
- `.toSpliced(...)` — `.splice()`의 불변 버전

```javascript
const reversed = #["Robin", "Rick", "Dan", "Nicolo", "Ashley"].toReversed();
assert(reversed === #["Ashley", "Nicolo", "Dan", "Rick", "Robin"]); // OK ✅
```

## 4. 제안 현황

- Record & Tuple은 **TC39 Stage 2** 제안. (위원회가 채택을 기대하지만 스펙은 최종본과 다를 수 있는 단계)
- Babel 트랜스폼·폴리필 존재, test262 스펙 테스트 작성됨, Firefox에 컴파일 플래그로 구현됨.
- 지금 실험해보려면 플레이그라운드: https://rickbutton.github.io/record-tuple-playground/
- 프로덕션 도입은 표준화 진행을 더 기다려야 한다.

### 📌 정리
`#{} / #[] = 언어가 보장하는 깊은 불변 + 값 동등성 원시 타입`

#### 핵심
> 객체는 참조·가변이라 불변성을 지키려면 freeze(얕음)·깊은 복사(느림)가 필요하고, Map 키로 쓰면 값이 같아도 참조가 달라 매칭이 안 된다. Record(`#{}`)와 Tuple(`#[]`)은 TC39 Stage 2 제안으로, 별도 처리 없이 **깊은 불변성**을 갖고 **값 기반 `===`** 비교가 되며 `typeof`가 `"record"`/`"tuple"`인 원시 타입이다. 단 내부에 일반 객체·함수는 못 담고, 업데이트는 스프레드 + `to*`/`with` 메서드로 한다.

#### ⭐️ 앞으로 기억할 것
- 1. `Object.freeze`는 얕다
  중첩 객체는 여전히 변경됨. 진짜 불변이 필요하면 깊은 복사(structuredClone)거나 Record/Tuple.
- 2. Record/Tuple은 값으로 비교된다
  ```javascript
  #{ a: 1 } === #{ a: 1 } // ✅  (객체였다면 🛑)
  ```
  이게 Map/Set 키, 메모이제이션, 의존성 비교에서 진가를 발휘한다.
- 3. 깊은 불변 + freeze 불필요
  선언만 하면 중첩까지 변경 불가. `config.db.host` 같은 깊은 값도 안전.
- 4. 객체·함수는 못 담는다
  `#{}` 안엔 원시값과 또 다른 `#{}`/`#[]`만. 함수 넣으면 TypeError.
- 5. 업데이트는 스프레드 + `to*`/`with`
  `push`/`sort`/`reverse` 같은 변경 메서드는 없음. `#[...a, ...b]`, `.toSorted()`, `.with(i, v)`로 새 값 생성.
- 6. 아직 Stage 2 — 프로덕션은 시기상조
  폴리필/Babel·Firefox 플래그로 실험만. 스펙 바뀔 수 있음.

📌 결론
▎ "불변성"을 라이브러리·freeze·복사 트릭이 아니라 언어 원시 타입으로 해결하려는 시도.
▎ 값 기반 동등성은 React 의존성 비교, 캐시 키, 상태 비교의 고질적 문제를 깔끔히 푼다.
▎ ⭐️ 실무 적용 포인트
  - 지금은 개념만 익혀두기 — 도입은 표준화 이후. ES2023의 `toSorted`/`with`가 같은 철학의 선행 주자.
  - 불변 데이터가 절실한 곳(설정 객체, 캐시 키)에서 미래에 자연스럽게 대체될 후보.
