# TanStack Router 소개

> **원문**: https://frontendmasters.com/blog/introducing-tanstack-router/
> **번역 출처**: https://velog.io/@eunbinn/introducing-tanstack-router

![](https://velog.velcdn.com/images/chromeheartz/post/02be1916-4ee0-4afb-aaca-340791252301/image.png)

TanStack Router에 대해 잘 정리된 글을 읽었다. 파일 기반 라우팅에 TypeScript를 깊게 통합해서 라우트 경로 자체까지 타입 검증이 된다는 게 인상적이었음. 기본 설정부터 검색 파라미터까지 단계별로 다뤄서 이해하기 좋았다.

---

### 기본 구조

TanStack Router는 파일 기반 라우팅을 사용한다. `npm run dev` 실행 시 라우트 파일 변경을 감지해서 `routeTree.gen.ts`를 자동으로 업데이트한다. 이 파일 덕분에 `<Link>`가 실제로 존재하는 경로를 가리키는지까지 컴파일 타임에 검증된다.

```
src/routes/
├── __root.tsx          ← 루트 레이아웃
├── index.tsx           ← /
├── tasks.route.tsx     ← /tasks 레이아웃
├── tasks.index.tsx     ← /tasks/
├── tasks.$taskId.index.tsx   ← /tasks/:taskId
└── tasks.$taskId.edit.tsx    ← /tasks/:taskId/edit
```

---

### 루트 라우트

`__root.tsx`가 모든 페이지에 적용되는 레이아웃이다. `<Outlet />`이 각 페이지가 렌더링되는 자리다.

```tsx
import { createRootRoute, Link, Outlet } from "@tanstack/react-router";

export const Route = createRootRoute({
  component: () => (
    <>
      <div>
        <Link to="/">Home</Link>
        <Link to="/tasks">Tasks</Link>
        <Link to="/epics">Epics</Link>
      </div>
      <hr />
      <Outlet />
    </>
  ),
});
```

`<Link>`는 현재 경로와 일치하면 `active` 클래스를 자동으로 붙여준다.

**타입 안정성 체험**: 위에서 `to="/"` 대신 존재하지 않는 경로를 넣으면 그 자리에서 TS 에러가 난다.

```
error TS2322: Type '"/없는경로"' is not assignable to type '"." | ".." | "/" | "/tasks" | ...
```

### 페이지 라우트

각 라우트 파일에서 `createFileRoute`로 해당 경로를 선언한다.

```tsx
// routes/index.tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/")({
  component: Index,
});

function Index() {
  return <h3>Top level index page</h3>;
}
```

### 레이아웃과 중첩 라우트

`tasks.route.tsx`는 `/tasks` 하위 경로 전체에 적용되는 레이아웃이다. `tasks.index.tsx`는 `/tasks/`의 실제 콘텐츠.

```tsx
// tasks.route.tsx — 레이아웃
export const Route = createFileRoute("/tasks")({
  component: () => (
    <div>
      Tasks layout <Outlet />
    </div>
  ),
});
```

```tsx
// tasks.index.tsx — 콘텐츠
export const Route = createFileRoute("/tasks/")({
  component: Index,
});

function Index() {
  const tasks = [
    { id: "1", title: "Task 1" },
    { id: "2", title: "Task 2" },
  ];

  return (
    <div>
      {tasks.map((t) => (
        <div key={t.id}>
          {t.title}
          <Link to="/tasks/$taskId" params={{ taskId: t.id }}>
            View
          </Link>
          <Link to="/tasks/$taskId/edit" params={{ taskId: t.id }}>
            Edit
          </Link>
        </div>
      ))}
    </div>
  );
}
```

`params`에도 타입이 걸려 있어서 `$taskId`에 맞지 않는 키를 넣으면 에러난다.

### 경로 파라미터

`$`로 동적 세그먼트를 선언하고, `Route.useParams()`로 꺼낸다.

```tsx
// tasks.$taskId.index.tsx
export const Route = createFileRoute("/tasks/$taskId/")({
  component: () => {
    const { taskId } = Route.useParams();
    return <div>View task {taskId}</div>;
  },
});
```

자동완성도 된다. `useParams()`의 반환값이 해당 라우트의 파라미터 타입으로 추론된다.

![경로 파라미터 자동완성](https://i0.wp.com/frontendmasters.com/blog/wp-content/uploads/2024/09/path-param-auto-complete.jpg)

### 고급 라우팅: URL 구조와 컴포넌트 계층 분리

파일명 규칙으로 URL과 레이아웃 중첩을 독립적으로 제어할 수 있다.

#### 언더스코어(`_`)로 레이아웃 제거

`tasks_.$taskId.edit.tsx` — 파일명에 `_`를 붙이면 해당 세그먼트의 레이아웃을 상속하지 않는다.

```
tasks.$taskId.edit.tsx   → /tasks/:taskId/edit  + tasks 레이아웃 포함
tasks_.$taskId.edit.tsx  → /tasks/:taskId/edit  + tasks 레이아웃 없음
```

![Tasks 레이아웃 없는 편집 화면](https://i0.wp.com/frontendmasters.com/blog/wp-content/uploads/2024/09/edit-task-without-tasks-layout.jpg)

#### 언더스코어 접두사로 경로 없는 레이아웃 추가

`_taskEdit.tsx`처럼 `_`로 시작하면 URL에 영향 없이 레이아웃만 추가하는 pathless 라우트가 된다.

```tsx
// _taskEdit.tsx
export const Route = createFileRoute("/_taskEdit")({
  component: () => (
    <div>
      Special Task Edit Layout <Outlet />
    </div>
  ),
});
```

```
_taskEdit.tasks_.$taskId.edit.tsx → URL: /tasks/:taskId/edit + 특별 레이아웃 적용
```

![경로 없는 레이아웃](https://i0.wp.com/frontendmasters.com/blog/wp-content/uploads/2024/09/pathless-layout.jpg)

### 디렉토리 기반 라우팅

플랫 파일 대신 디렉토리 구조를 써도 된다. 취향 차이.

```
routes/epics/
├── index.tsx     ← epics.index.tsx 와 동일
├── route.tsx     ← epics.route.tsx 와 동일
└── $epicId/
    └── milestones/
        └── index.tsx
```

중첩 파라미터도 한 번에 꺼낼 수 있다:

```tsx
const { epicId, milestoneId } = Route.useParams();
```

### 검색 파라미터 (쿼리스트링)

검색 파라미터도 타입 정의 + 검증까지 라우트 단에서 처리한다.

```tsx
type SearchParams = {
  page: number;
  search: string;
  tags: string[];
};

export const Route = createFileRoute("/epics/$epicId/milestones/")({
  validateSearch(search: Record<string, unknown>): SearchParams {
    return {
      page: Number(search.page ?? "1") ?? 1,
      search: (search.search as string) || "",
      tags: Array.isArray(search.tags) ? search.tags : [],
    };
  },
  component: Milestones,
});
```

#### 검색 파라미터 읽기

```tsx
import { getRouteApi } from "@tanstack/react-router";

const route = getRouteApi("/epics/$epicId/milestones/");
const { page, search, tags } = route.useSearch();
```

#### 검색 파라미터 업데이트

```tsx
const navigate = useNavigate({ from: "/epics/$epicId/milestones/" });

// 다음 페이지로
navigate({
  to: ".",
  search: (prev) => ({ ...prev, page: prev.page + 1 }),
});

// 검색어 + 태그 변경
navigate({
  to: ".",
  search: (prev) => ({ page: 1, search: "Hello", tags: ["tag1", "tag2"] }),
});
```

#### Link에서 검색 파라미터 전달

```tsx
<Link
  to="/epics/$epicId/milestones"
  params={{ epicId }}
  search={{ search: "", page: 1, tags: [] }}
>
  View milestones
</Link>
```

`search`도 타입 검증된다. 누락되거나 타입이 틀리면 에러.

#### URL 간결화 — 기본값이면 URL에서 제거

기본값인 파라미터는 URL에 포함시키지 않으려면 `Partial` 타입과 검증 로직 수정으로 처리한다.

```tsx
type SearchParams = Partial<{
  page: number;
  search: string;
  tags: string[];
}>;

validateSearch(search): SearchParams {
  const page = Number(search.page ?? "1") ?? 1;
  const searchVal = (search.search as string) || "";
  const tags = Array.isArray(search.tags) ? search.tags : [];

  return {
    page: page === 1 ? undefined : page,       // 1이면 URL에서 생략
    search: searchVal || undefined,             // 빈 문자열이면 생략
    tags: tags.length ? tags : undefined,       // 빈 배열이면 생략
  };
}
```

### 📌 정리

`라우트 경로와 파라미터까지 타입으로 검증하는 라우터`

#### 핵심

> TanStack Router는 파일 기반 라우팅 + TypeScript 깊은 통합이 핵심이다.
> `<Link to="...">` 자체가 존재하지 않는 경로를 가리키면 빌드 타임 에러가 난다.

#### ⭐️ 앞으로 기억할 것

- 1. **`routeTree.gen.ts` — 건드리지 말 것**
     dev 서버가 라우트 파일 변경 감지 시 자동 생성. 여기서 모든 타입 정보가 나온다.

- 2. **파일명 규칙이 곧 라우트 구조**

```
tasks.route.tsx         → /tasks 레이아웃
tasks.index.tsx         → /tasks/ 콘텐츠
tasks.$taskId.index.tsx → /tasks/:taskId
tasks_.$taskId.edit.tsx → tasks 레이아웃 제거
_layout.some.route.tsx  → URL 없는 레이아웃 추가
```

- 3. **검색 파라미터도 validateSearch로 타입 보장**
     URL에서 들어오는 값은 항상 `unknown` — `validateSearch`가 파싱 + 타입 변환을 담당한다.

```tsx
validateSearch(search: Record<string, unknown>): SearchParams {
  return { page: Number(search.page ?? 1) };
}
```

- 4. **navigate의 search 콜백 패턴**
     기존 파라미터를 유지하면서 일부만 바꿀 때 `(prev) => ({ ...prev, page: 2 })` 패턴 유용.

- 5. **`getRouteApi`로 컴포넌트 외부에서 라우트 접근**
     훅 대신 라우트 API 객체를 만들어두고 `useSearch()`, `useParams()`를 호출하는 방식.

> **📌 결론**
> ▎ 파일 기반 라우팅 + 자동 생성 타입으로 라우트 관련 런타임 에러를 빌드 타임으로 당긴다
> ▎ 언더스코어 규칙만 익히면 URL 구조와 레이아웃 중첩을 자유롭게 분리할 수 있다
> ▎ ⭐️ 검색 파라미터를 URL로 관리할 때 `validateSearch` + `navigate` 콜백 패턴이 핵심
