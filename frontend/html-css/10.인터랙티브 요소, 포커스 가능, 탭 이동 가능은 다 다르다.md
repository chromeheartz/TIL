# 인터랙티브 요소, 포커스 가능, 탭 이동 가능은 다 다르다

> **원문**: [What's an interactive element?](https://www.matuzo.at/blog/2025/whats-an-interactive-element) — Manuel Matuzović
> **번역 출처**: [[번역] 인터랙티브 요소란 무엇일까?](https://devowen.com/554) — DevOwen

모달 만들 때 `<dialog>`에 `tabindex="-1"` 붙여도 되나 헷갈린 적이 있어서 읽어봤다. MDN에는 "dialog는 인터랙티브하지 않고 포커스도 안 받으니 tabindex 넣지 마라"라고 써 있는데, 글쓴이는 이 문장이 틀렸다고 말한다. 결국 핵심은 **인터랙티브 / 포커스 가능 / 탭 이동 가능**이 서로 다른 개념이라는 것.

### 발단: MDN의 dialog 경고

![MDN dialog 페이지의 tabindex 경고](https://www.matuzo.at/media/pages/blog/2025/whats-an-interactive-element/7f808cccb9-1780687544/warning.png)

MDN `<dialog>` 페이지 상단에 빨간 경고가 붙어 있다. 근거는 [`HTML 명세`][spec-dialog]에 "dialog 요소에는 tabindex를 지정하면 안 된다"고 적혀 있기 때문.

그러니까 명세 기준으로는 MDN 말이 맞다. 그런데 글쓴이 입장은 이렇다.

- `dialog`에 `tabindex`를 넣어도 **아무것도 안 망가진다**
- 그냥 dialog가 [`포커스를 알아서 잘 처리`][focus-dialog]하니까 **필요 없을 뿐**
- 그러니 "넣지 마라"보다는 "넣을 필요 없다"가 맞는 표현

진짜 문제는 그 뒤의 설명 — "dialog는 인터랙티브하지 않고 포커스를 받지 않는다". 이건 **둘 다 틀렸다.** 직접 해보면 바로 보인다.

```js
button.addEventListener('click', () => {
  dialog.showModal();
  // DIALOG 출력 → dialog 자체가 포커스를 받았다
  output.textContent = document.activeElement.tagName;
});
```

(안에 포커스 가능한 요소가 없을 때 이렇게 된다.)

### 인터랙티브 요소란

[`HTML 명세의 포커스 절`][spec-focus]은 첫 문장부터 UI를 폼 컨트롤, 스크롤 영역, 링크, **다이얼로그 박스**, 브라우저 탭 같은 인터랙티브 위젯의 계층으로 설명한다. 다이얼로그는 다른 인터랙티브 요소를 **담는** 인터랙티브 요소라는 것. 이걸로 답은 이미 나왔다.

그리고 인터랙티브 요소는 포커스를 받을 수 있으니 **포커스 가능 영역(focusable area)** 이 된다.

#### 포커스 가능 영역의 조건

요소가 포커스 가능 영역이 되려면 아래를 **모두** 만족해야 한다.

| 조건 | 깨지는 예 |
|------|-----------|
| `tabindex` 값이 있거나, 브라우저가 포커스 가능하다고 판단 | 그냥 `<div>` |
| 섀도우 호스트가 아니거나, 섀도우 루트의 `delegatesFocus`가 false | `delegatesFocus: true`인 커스텀 요소 |
| 실제로 비활성화되지 않음 | `<button disabled>` |
| inert 상태가 아님 | `<button inert>` |
| 렌더링 중이거나, 렌더링을 자식에게 위임 중 | `hidden`, `display: none` |

요소 말고도 포커스 가능 영역이 되는 것들이 있다.

- 이미지 맵 `area`의 도형
- 브라우저가 제공하는 하위 위젯 — `<video controls>`의 컨트롤, `<input type=number>`의 위아래 버튼
- **스크롤 가능한 영역** — `div`도 넘치면 인터랙티브해진다 (이럴 땐 레이블 붙은 시맨틱 요소를 쓰는 게 낫다)
- `iframe` 같은 문서의 뷰포트
- 그 외 브라우저가 접근성/플랫폼 관례상 포커스 가능하다고 판단한 것

#### 헷갈렸던 예시들

```html
<!-- ✅ tabindex 값이 있음 → 포커스 가능 -->
<section tabindex="-1" aria-label="Results"></section>

<!-- ✅ 브라우저가 포커스 가능하다고 판단 -->
<dialog></dialog>

<!-- ❌ 비활성화 / inert → 포커스 불가 -->
<button disabled>disabled</button>
<button inert>inert</button>

<!-- ❌ 렌더링 안 됨 → 포커스 불가 -->
<button hidden>hidden</button>
<button style="display: none">none</button>

<!-- ✅ div는 렌더링 안 되지만 자식 button은 렌더링됨 → button은 포커스 가능 -->
<div style="display: contents">
  <button>여전히 포커스 됨</button>
</div>
```

섀도우 DOM 쪽이 제일 의외였다. `tabindex="0"`을 줘도 포커스를 안쪽으로 위임하면 호스트 자체는 포커스를 못 받는다.

```js
class TheButton extends HTMLElement {
  constructor() {
    super();
    // delegatesFocus: true → 호스트 대신 안쪽 button이 포커스를 받음
    this.attachShadow({ mode: 'open', delegatesFocus: true });
    const button = document.createElement('button');
    button.textContent = 'Focus me';
    this.shadowRoot.append(button);
  }
}
customElements.define('the-button', TheButton);
```

### 포커스 가능하다는 건

정의는 생각보다 단순하다. **`focus()`나 `autofocus`로 프로그래밍 방식으로 포커스를 줄 수 있으면 포커스 가능.**

여기에 사용자 입력 기준으로 두 가지 축이 더 있다. 둘 다 / 하나만 / 둘 다 아님, 전부 가능하다.

#### 순차적으로 포커스 가능 (= tabbable)

Tab 키로 도달할 수 있는 요소. [`명세`][spec-tabindex]가 플랫폼 관례상 권장하는 목록은 이렇다.

- `href`가 있는 `<a>`
- `<button>`
- `<input>` (`type="hidden"` 제외)
- `<select>`, `<textarea>`
- `<details>`의 첫 번째 `<summary>`
- 편집 호스트 (`contenteditable`, design mode 문서)
- `<iframe>` 같은 내비게이션 가능한 컨테이너
- `tabindex`가 0 이상인 요소

#### 클릭으로 포커스 가능

클릭해서 포커스가 가는 요소.

```html
<button>button</button>
<dialog open>dialog</dialog>
<div tabindex="-1">tabindex=-1</div>
```

| 요소 | Tab | 클릭 |
|------|-----|------|
| `button` | ✅ | ✅ |
| 열린 `dialog` | Firefox 144 ❌ / Chrome 141·Safari 18.6 ✅ | ✅ |
| `div tabindex="-1"` | ❌ | ✅ |

dialog가 브라우저마다 다른 건 꽤 재밌는 포인트. 아무튼 **탭 이동은 안 돼도 포커스 가능할 수 있다.**

#### 둘 다 안 되는데 포커스는 되는 경우

`tabindex="-1"` + `pointer-events: none`이면 Tab도 클릭도 안 먹지만, 레이블을 누르거나 `focus()`를 호출하면 포커스가 간다.

```html
<label for="r">Read only</label>
<!-- readonly input은 원래 tabbable. 데모용으로 tabindex=-1 추가 -->
<input type="text" id="r" tabindex="-1" readonly style="pointer-events: none">
```

### 인터랙티브하지 않은 요소에 tabindex 넣어도 될까

MDN `tabindex` 페이지는 "인터랙티브하지 않은 콘텐츠에 tabindex 쓰지 마라"고 하는데, 앞에서 본 잘못된 정의를 그대로 따르면 이상한 결론이 나온다. 음수도 안 되고 양수도 안 된다면 `0`만 남는데, `0`은 이미 포커스 가능한 요소에 아무 효과도 없다. 하하.

글쓴이 결론은 **접근성에 도움이 되면 `tabindex="-1"`은 괜찮다.** 대표적인 게 CSR 앱에서 사용자를 특정 위치로 옮겨주는 경우.

```html
<!-- 검색 버튼 클릭 후 결과 컨테이너로 포커스 이동 -->
<section tabindex="-1" aria-labelledby="heading">
  <h2 id="heading">42 search results</h2>
  …
</section>

<!-- 이것도 OK: 프로그래밍 방식 포커스만, 탭 이동은 안 됨 -->
<h2 tabindex="-1">42 search results</h2>
```

대신 지켜야 할 것 두 가지.

- 제네릭 요소(`div`, `span`) 말고 **레이블 붙은 시맨틱 요소**에 쓴다
- 인터랙티브하지 않은 요소를 **tabbable하게 만들진 않는다**

```html
<!-- ❌ div를 버튼처럼 -->
<div tabindex="0" onclick="search()">검색</div>

<!-- ✅ 그냥 button -->
<button type="button" onclick="search()">검색</button>
```

### 📌 정리

`포커스 가능 ⊃ 탭 이동 가능`

#### 핵심

> `dialog`는 인터랙티브 요소이고 포커스도 받는다. MDN 경고의 근거는 명세지만, 실제로는 "필요 없다"에 가깝다.
> 포커스 가능 = `focus()`로 포커스를 줄 수 있음. 그 안에서 Tab(순차) / 클릭 포커스 가능 여부는 별개다.
> 접근성에 도움이 되면 시맨틱 요소에 `tabindex="-1"`은 문제없다. 단 비인터랙티브 요소를 tabbable로 만들진 말 것.

#### ⭐️ 앞으로 기억할 것

- 1. 세 단어를 구분해서 쓰자
인터랙티브 → 포커스 가능 영역이 됨. 포커스 가능 → `focus()` 가능. 탭 이동 가능 → Tab으로 도달. 리뷰할 때 "포커스 안 돼요"가 어느 쪽 얘기인지부터 확인한다.

- 2. `tabindex` 값별 의미
| 값 | 의미 |
|----|------|
| 없음 | 요소 기본 동작 |
| `-1` | 프로그래밍(+클릭) 포커스만, 탭 순서에서 빠짐 |
| `0` | DOM 순서대로 탭 순서에 포함 |
| `1+` | 탭 순서 강제 — 쓰지 말자 |

- 3. 라우트 전환/검색 결과 후 포커스 이동 패턴
SPA에서 화면 바뀌면 포커스가 엉뚱한 데 남는다. 제목에 `tabindex="-1"` 주고 `focus()`.
```tsx
const headingRef = useRef<HTMLHeadingElement>(null);

useEffect(() => {
  headingRef.current?.focus(); // 결과 렌더 후 제목으로 포커스 이동
}, [results]);

// React에서는 tabIndex (camelCase)
return <h2 ref={headingRef} tabIndex={-1}>{results.length} search results</h2>;
```

- 4. 포커스가 안 될 때 체크리스트
`disabled` / `inert` / `hidden`·`display: none` / 섀도우 `delegatesFocus` 순서로 의심한다.

- 5. dialog는 `showModal()`에 맡긴다
dialog에 `tabindex`를 억지로 넣는 것보다, 처음 포커스 받을 요소에 `autofocus`를 주는 게 더 낫다.

> **📌 결론**
> ▎ `dialog`는 인터랙티브하고 포커스도 받는다
> ▎ 포커스 가능하다고 다 탭 이동 가능한 건 아니다
> ▎ `disabled`, `inert`, 렌더링 여부, `delegatesFocus`가 포커스 가능 여부를 가른다
> ▎ 시맨틱 요소에 `tabindex="-1"`은 접근성 도구
> ▎ ⭐️ 실무 적용 포인트: 클릭 가능한 `div`는 `button`으로 바꾸고, 화면 전환 후엔 제목에 `tabIndex={-1}` + `focus()`로 포커스를 옮긴다
