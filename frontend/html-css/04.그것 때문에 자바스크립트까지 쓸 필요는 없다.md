# 그것 때문에 자바스크립트까지 쓸 필요는 없다

> **원문**: https://www.htmhell.dev/adventcalendar/2023/2/
> **번역 출처**: https://velog.io/@eunbinn/You-dont-need-JavaScript-for-that

스위치, 자동완성, 컬러피커, 아코디언, 모달… 습관적으로 JS 라이브러리부터 깔던 것들인데, 사실 HTML/CSS만으로 되는 게 꽤 많다. "JS가 필요하다는 걸 안다고 해서, 진짜 JS가 필요한 건 아니다"라는 문장이 인상 깊어서 정리해둠.

![post-thumbnail](https://velog.velcdn.com/images/eunbinn/post/f5e925dd-3a33-490b-a101-8092ebfdf436/image.png)

### 가장 적은 힘의 원칙 (Rule of Least Power)

> 목적에 맞는 가장 **덜 강력한** 언어를 골라라.

HTML/CSS는 선언형(declarative)이라 "무엇을" 원하는지만 적으면 브라우저가 알아서 성능·접근성을 최적화해준다. 반면 JS는 명령형(imperative)이라 "어떻게"를 전부 내가 써야 하고, 상태 관리·접근성·포커스 처리까지 직접 떠안게 된다.

즉 우선순위는 `HTML > CSS > JS`. 아래 케이스들이 그 증거다.

### 커스텀 스위치 — checkbox + `:checked`

토글 스위치 만들겠다고 JS로 상태 들고 다닐 필요 없다. 그냥 네이티브 체크박스에 `appearance: none` 주고 CSS로 칠하면 끝. 상태는 브라우저가 `:checked`로 관리해준다.

```html
<label>
  <input type="checkbox" />
  My awesome feature
</label>
```

`appearance: none`으로 기본 모양을 지우고, 가상요소 `::before`로 동그란 손잡이(thumb)를 만든다:

```css
input {
  appearance: none; /* 기본 체크박스 UI 제거 → 마음대로 스타일링 */
  position: relative;
  display: inline-block;
  background: lightgrey;
  height: 1.65rem;
  width: 2.75rem;
  vertical-align: middle;
  border-radius: 2rem;
  box-shadow: 0px 1px 3px #0003 inset;
  transition: 0.25s linear background;
}

input::before {
  content: "";
  display: block;
  width: 1.25rem;
  height: 1.25rem;
  background: #fff;
  border-radius: 1.2rem;
  position: absolute;
  top: 0.2rem;
  left: 0.2rem;
  box-shadow: 0px 1px 3px #0003;
  transition: 0.25s linear transform;
  transform: translateX(0rem);
}
```

![appearance:none로 모양 잡힌 스위치](https://velog.velcdn.com/images/eunbinn/post/b1543e0d-7d93-49d6-ad57-16c00d0a23de/image.gif)

체크되면 색 바꾸고 손잡이를 오른쪽으로 밀어준다 — 이게 핵심. JS 한 줄도 없다:

```css
:checked {
  background: green;
}

:checked::before {
  transform: translateX(1rem);
}
```

![:checked로 토글되는 스위치](https://velog.velcdn.com/images/eunbinn/post/a375ad25-d8f2-4f55-8dee-2c2dbabf1395/image.gif)

![transition으로 부드럽게 미끄러지는 손잡이](https://velog.velcdn.com/images/eunbinn/post/10a90d55-f314-48be-a622-7c8beef42695/image.gif)

접근성 포인트: 포커스 링은 살려둬야 한다. `:focus-visible`로 키보드 포커스만 표시:

```css
input:focus-visible {
  outline: 2px solid dodgerblue;
  outline-offset: 2px;
}

input:focus {
  outline-color: transparent;
}
```

![키보드 포커스 시에만 나타나는 outline](https://velog.velcdn.com/images/eunbinn/post/354c30b1-341f-4e94-9ee4-f0a1170148de/image.gif)

> 네이티브 체크박스를 쓰니 키보드 조작·스크린리더·`label` 연결이 **공짜로** 따라온다. 커스텀 `<div>`로 만들었으면 이걸 다 손으로 구현해야 했을 거다.

### 자동완성 — `<datalist>`

자동완성 컴포넌트 라이브러리 깔기 전에 `<datalist>`부터 떠올리자. `input`에 `list` 속성으로 연결하면 브라우저가 입력값에 맞춰 필터링까지 해준다.

```html
<input list="frameworks" />
<datalist id="frameworks">
  <option>Bootstrap</option>
  <option>Tailwind CSS</option>
  <option>Foundation</option>
  <option>Bulma</option>
  <option>Skeleton</option>
</datalist>
```

![datalist 네이티브 자동완성 필터링](https://velog.velcdn.com/images/eunbinn/post/a30c26f8-c953-4245-b675-aef78e0b313d/image.gif)

### 컬러 피커 — `<input type="color">`

색상 선택 UI도 네이티브가 있다. Chromium 계열은 "화면 아무 곳이나 스포이드로 찍기"까지 기본 제공.

```html
<label>
  <input type="color" />
  Color
</label>
```

![네이티브 컬러 피커 UI](https://velog.velcdn.com/images/eunbinn/post/5a34b1db-2b73-4135-9954-a7ff91002971/image.gif)

### 아코디언 — `<details>` / `<summary>`

열고 닫는 상태를 JS로 토글하지 말자. `<details>`가 열림/닫힘 상태를 알아서 관리한다. `<summary>`가 클릭 가능한 헤더.

```html
<details>
  <summary>My accordion</summary>
  <p>My accordion content</p>
</details>
```

![details/summary 기본 아코디언 토글](https://velog.velcdn.com/images/eunbinn/post/82da89b0-65b8-44da-a403-9d51e5e25687/image.gif)

`open` 속성을 붙이면 기본 펼침 상태:

```html
<details open>
  <summary>My accordion</summary>
  <p>My accordion content</p>
</details>
```

![open 속성으로 펼쳐진 상태](https://velog.velcdn.com/images/eunbinn/post/0b2fb0b5-5c3e-4166-a60e-df72ea36251a/image.gif)

펼침/접힘 표시(▶)는 `::marker`로 커스텀. 열린 상태는 `[open]` 속성 선택자로 분기:

```css
summary::marker {
  font-size: 1.5em;
  content: "📬"; /* 닫혔을 때 */
}

[open] summary::marker {
  font-size: 1.5em;
  content: "📭"; /* 열렸을 때 */
}
```

![::marker 이모지로 바뀌는 펼침 표시](https://velog.velcdn.com/images/eunbinn/post/81b61db5-84e9-4af2-90ee-a249a5a902f6/image.gif)

```css
summary:hover,
summary:focus {
  cursor: pointer;
  background: deeppink;
}
```

![summary hover/focus 스타일](https://velog.velcdn.com/images/eunbinn/post/f716ddb8-f5b2-426f-8ceb-ea2aadd1e478/image.gif)

### 모달 — `<dialog>` + `showModal()`

모달이야말로 직접 만들면 지옥이다. 포커스 트랩, 백그라운드 클릭 막기, top-layer 쌓임 순서… 전부 신경 써야 한다. `<dialog>`는 이걸 `showModal()` 한 번으로 다 처리해준다.

```html
<dialog>
  <form method="dialog">
    <h3>This is a pretty dialog</h3>
    <button type="submit">Close</button>
  </form>
</dialog>
```

`showModal()`로 열면 포커스 트랩 + 배경 비활성화가 자동:

```javascript
document.querySelector("button").addEventListener("click", () => {
  document.querySelector("dialog").showModal();
});
```

![showModal()로 열리는 네이티브 모달](https://velog.velcdn.com/images/eunbinn/post/c88a6ae3-5fed-46c1-931d-bb4dfc5cf71c/image.gif)

`method="dialog"` 폼은 버튼의 `value`를 결과로 넘긴다. 확인 다이얼로그를 이렇게:

```html
<dialog>
  <form method="dialog">
    <p>Tabs or spaces?</p>
    <button type="submit" value="wrong">Tabs</button>
    <button type="submit" value="correct">Spaces</button>
  </form>
</dialog>
```

`close` 이벤트에서 `returnValue`로 어떤 버튼을 눌렀는지 읽는다:

```javascript
dialog.addEventListener("close", function () {
  console.log(dialog.returnValue); // "wrong" 또는 "correct"
});
```

![버튼 value로 결과를 받는 확인 다이얼로그](https://velog.velcdn.com/images/eunbinn/post/1a4dcacd-2b15-40b6-b097-953b2a6cac40/image.gif)

뒤에 깔리는 오버레이는 `::backdrop` 가상요소로 스타일링 — 블러까지 CSS로:

```css
dialog::backdrop {
  background: #fff5;
  backdrop-filter: blur(4px);
}
```

![::backdrop 블러 오버레이](https://velog.velcdn.com/images/eunbinn/post/d1b445eb-2a44-4c0c-803c-36dd14fc5529/image.gif)

> 여기서 JS는 "여는 트리거"와 "결과 읽기"에만 쓰인다. 모달의 까다로운 동작(포커스/접근성/레이어)은 전부 브라우저 몫.

### 📌 정리
`스위치·자동완성·컬러피커·아코디언·모달은 네이티브로 된다`

#### 핵심
> JS 라이브러리부터 깔기 전에 HTML/CSS 네이티브를 먼저 확인하자. `appearance:none` + `:checked`(스위치), `<datalist>`(자동완성), `<input type=color>`(컬러), `<details>/<summary>`(아코디언), `<dialog>+showModal()`(모달) — 이것들은 상태 관리·접근성·포커스 처리를 **브라우저가 공짜로** 해준다. "가장 적은 힘의 원칙": 목적에 맞는 가장 덜 강력한 언어(HTML > CSS > JS)를 골라라.

#### ⭐️ 앞으로 기억할 것
- 1. 토글 스위치는 체크박스를 칠하는 것
  네이티브 `<input type=checkbox>` + `appearance:none` + `:checked`. 키보드·스크린리더·label 연결이 따라온다.
  ```css
  :checked::before { transform: translateX(1rem); }
  ```
- 2. 자동완성/컬러는 input이 이미 한다
  `<input list>` + `<datalist>`, `<input type="color">`. 라이브러리 의존성 0.
- 3. 아코디언은 `<details>`, 마커는 `::marker`
  열림 상태는 `[open]` 속성 선택자로 분기.
  ```css
  [open] summary::marker { content: "📭"; }
  ```
- 4. 모달은 `<dialog>` + `showModal()`
  포커스 트랩·top-layer·배경 비활성화 자동. 오버레이는 `::backdrop`. 결과는 `form method="dialog"`의 `value` → `dialog.returnValue`로 읽는다.

📌 결론
▎ 네이티브 요소는 접근성·포커스·상태를 공짜로 준다 — 직접 만들면 그걸 다 떠안는 거다.
▎ JS는 "정말 필요한 곳"(트리거, 결과 처리)에만 남기고 나머지는 브라우저에 맡겨라.
▎ ⭐️ 실무 적용 포인트: 새 UI 컴포넌트 만들기 전에 "이거 네이티브 HTML 요소 없나?"를 먼저 검색하는 습관. 십중팔구 있다.
