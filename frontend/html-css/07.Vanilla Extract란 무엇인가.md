# Vanilla Extract란 무엇인가

> 원문: [Vanilla Extract란 무엇인가](https://velog.io/@keumky1/Vanilla-Extract%EB%9E%80-%EB%AC%B4%EC%97%87%EC%9D%B8%EA%B0%80) — 금교영

styled-component, emotion 같은 런타임 CSS-in-JS를 쭉 써오다가 "성능 떨어진다"는 얘기를 종종 들었는데, 그 대안으로 나온 **Zero-runtime CSS-in-JS** 중 하나인 `Vanilla Extract`를 정리한 글이다. 한 줄로 요약하면 **"빌드타임에 .ts를 .css로 뽑아내는 CSS Modules-in-TypeScript"**. 왜 런타임 방식이 느린지부터 짚고 들어가는 게 좋았다.

## 런타임 CSS-in-JS의 문제

React가 뜨면서 CSS-in-JS도 같이 인기를 얻었다. 장점은 분명하다:

- CSS에서 JS 문법을 쓸 수 있어 생산성 🔼
- 컴포넌트 파일에 관련 코드를 같이 둘 수 있음 ([colocation](https://kentcdodds.com/blog/colocation)) — 예전엔 css/js 파일을 분리해야 했음
- className 충돌 안 함 보장 (지역 스코프 스타일)

근데 단점이 있다. **런타임 CSS-in-JS는 런타임에 js가 실행되면서 style을 생성한다.** 스타일 생성 규모가 크고 빈번할수록 성능이 떨어진다. 예를 들어 share 버튼을 누르면 `loading` 상태가 `true`가 되고 글자색이 회색으로 바뀌는 버튼:

![상태마다 다른 스타일](https://velog.velcdn.com/images/keumky1/post/a10a4a3f-395f-48cd-b4c0-861b7e7e1be6/image.png)

```javascript
const [isLoading, setIsLoading] = useState(false)

<ShareButton isLoading={isLoading}> Share </ShareButton>

const ShareButton = styled.button<{isLoading: boolean}>`
  color: ${({isLoading}) => isLoading ? "gray" : "black"}
`
```

버튼을 누르면 상태가 변하고 ShareButton이 리렌더 = **함수가 다시 실행된다.** CSS-in-JS가 런타임에 스타일을 넣는 방식은 대개 두 가지:

1. `<head>`에 `<style>` 태그를 만들어 삽입
2. [`CSSStyleSheet.insertRule`](https://developer.mozilla.org/en-US/docs/Web/API/CSSStyleSheet/insertRule)로 CSSOM에 직접 삽입 (이 경우 style 태그가 비어 보이고, `document.styleSheets[0].cssRules`로 확인 가능)

2번 기준으로 보면 — 초기엔 isLoading이 false라 `.ghhwYS { color: black; }`가 `cssRules`에 삽입되고, 클릭 후엔 다시 스타일을 **계산**해서 `.iXkpNI { color: gray; }`를 추가한다. 즉 매 리렌더마다 스타일 계산+삽입이 일어난다.

성능 문제를 체감하려면? 스타일 컴포넌트에 느린 코드를 넣고 여러 개 렌더링하면 클릭 후 2~3초 뒤에야 리렌더가 끝나는 걸 볼 수 있다.

```javascript
const colorArr = ['skyblue', 'red', 'gray', 'mint', 'blue'];

const Button = styled.button<{ count: number }>`
  font-size: 17px;
  &:hover {
    background-color: ${({ count }) => {
      const s = Array(10000000).map(() => 1); // 일부러 무거운 코드
      return colorArr[count];
    }};
  }
`;
// ...여러 개 렌더링
```

## Vanilla Extract

이 문제를 풀려고 **Zero-runtime CSS-in-JS**가 등장했다. `Linaria`, `Stitches`, `Vanilla Extract` 등이 있는데 이 글은 [Vanilla Extract](https://vanilla-extract.style/)를 다룬다. 기본 컨셉은 **`CSS Modules-in-TypeScript`**:

- **빌드타임에 .ts → .css 변환** (sass와 같음) → 런타임 계산 없음
- **type-safe**하게 theme를 다룸
- 프론트엔드 프레임워크에 구애받지 않음
- `Tailwind`처럼 Atomic CSS 구성 가능 (Sprinkles)
- `Stitches`처럼 variant 기반 스타일링 가능 (Recipes)

## 활용 방법

### 시작하기
빌드타임에 css로 변환돼 head에 삽입되므로 **번들러 설정이 필수**다. 거의 모든 번들러를 지원([bundler-integration](https://vanilla-extract.style/documentation/getting-started#bundler-integration)).

### 스타일 만들기
```javascript
// style.css.ts
import { style } from '@vanilla-extract/css';

export const myStyle = style({
  display: 'flex',
  paddingTop: '3px',
  fontSize: '42px',
});

// App.tsx
<div className={myStyle}>안녕하세요</div>

// 결과물 — 빌드타임에 고유 className으로 변환
// .s_myStyle__t0h71y0 { display: flex; padding-top: 3px; font-size: 42px; }
```

`myStyle`은 빌드타임에 `s_myStyle__t0h71y0` 같은 className으로 바뀐다.

```javascript
export const flexCenter = style({
  padding: 10,    // 숫자만 쓰면 자동으로 10px
  marginTop: 25,
  display: 'center',
  alignItems: 'center',
  justifyContent: 'center',
});
```

CSS 변수는 [`createVar`](https://vanilla-extract.style/documentation/api/create-var/)로 (고유한 변수명 생성):

```javascript
import { style, createVar } from '@vanilla-extract/css';

const myVar = createVar(); // 결과: --myVar__t0h71y2

const myStyle = style({
  vars: {
    [myVar]: 'purple'
    // '--purple_color': 'purple' 처럼 createVar 없이 직접 써도 됨
  }
});
```

스타일 합성도 됨 — className이 합쳐져서 나온다:
```javascript
const base = style({ padding: 12 }); // s_base__t0h71y4
const secondary = style([base, { background: 'aqua' }]);
// → s_base__t0h71y4  s_secondary__t0h71y6
```

### 테마 만들기
[`createTheme`](https://vanilla-extract.style/documentation/api/create-theme/) — CSS 변수를 만들고 값을 부여하는 방식. **반환값이 `[themeClass, vars]` 두 개**라는 게 핵심:

```javascript
export const [themeClass, vars] = createTheme({
  color: { brand: 'blue' },
  font: { body: 'arial' }
});
```

- **`vars`** = 변수명들이 담긴 객체 (테마가 어떤 변수를 갖는지 알려주는 **스키마/템플릿**)
- **`themeClass`** = 변수에 실제 값을 매핑해둔 스타일 조각의 **className**

```javascript
// vars = 스키마
export const vars = {
  color: { brand: 'var(--color-brand__l520oi1)' },
  font: { body: 'var(--font-body__l520oi2)' }
};
// themeClass = 실제 값을 박아둔 클래스
export const themeClass = 'theme_themeClass__l520oi0';
// .theme_themeClass__l520oi0 {
//   --color-brand__l520oi1: blue;
//   --font-body__l520oi2: arial;
// }
```

테마를 지정하고 스타일에 적용:
```javascript
// style.css.ts
export const brandText = style({
  color: vars.color.brand, // var(--color-brand__l520oi1)
  font: vars.font.body,
});

// App.tsx — 상위에 themeClass, 안쪽에 brandText
function App() {
  return (
    <div className={themeClass}>
      <div className={brandText}>안녕하세요</div>
    </div>
  );
}
```

**`vars`로 또 다른 테마를 만들 수 있다.** `createTheme(vars, 값)` 형태로 — 형태(vars)는 고정하고 값만 바꿔 끼우는 격. 상위에서 className만 토글하면 테마 전환:
```javascript
export const [themeClass, vars] = createTheme({
  color: { brand: 'blue' }, font: { body: 'arial' }
});

export const otherThemeClass = createTheme(vars, {
  color: { brand: 'red' }, font: { body: 'helvetica' }
});

// App.tsx
function App() {
  const [isPrimary, setIsPrimary] = useState(false);
  return (
    <div className={isPrimary ? themeClass : otherThemeClass}>
      <div className={brandText}>안녕하세요</div>
    </div>
  );
}
```

### Sprinkles — Atomic CSS를 쉽게 (Tailwind 모방)
매번 `vars.color.brand`처럼 길게 쓰던 걸 짧게. 프로퍼티를 정의하고 `createSprinkles`로 만든다. 프로퍼티가 하나하나 쪼개져 각자 className을 가진 스타일 조각이 된다(Tailwind와 비슷):

```javascript
import { defineProperties, createSprinkles } from '@vanilla-extract/sprinkles';

const colors = {
  'brand': vars.color.brand,
  'secondary': vars.color.secondary,
};

const colorProperties = defineProperties({
  properties: { color: colors }
});

export const sprinkles = createSprinkles(colorProperties);
export type Sprinkles = Parameters<typeof sprinkles>[0]; // 타입도 export 권장
```

`style` 함수와 섞어 쓰거나, runtime에도 사용 가능:
```javascript
export const container = style([
  sprinkles({ color: 'brand' }),
  { ':hover': { outline: '2px solid currentColor' } }
]);

// 혹은 runtime에
<div className={sprinkles({ color: 'brand' })}>안녕하세요</div>
```

### Recipes — variant 기반 스타일링 (Stitches 모방)
"테두리 색과 텍스트 색이 같은 Box가 orange/blue 두 종류" 같은 걸 **variant(변형)**로 묶어서 표현. 같은 기능 컴포넌트를 여러 모양으로:

![](https://velog.velcdn.com/images/keumky1/post/3f54cd6f-5ff9-4e17-9c28-a4442fd93ca8/image.png)

```javascript
export const button = recipe({
  base: { borderRadius: 6, outline: 'solid' }, // 공통 base
  variants: {
    color: {
      orange: { color: 'orange', outlineColor: 'orange' },
      blue: { color: 'blue', outlineColor: 'blue' },
    },
  },
  defaultVariants: { color: 'blue' }, // fallback
});

<div className={button({ color: 'blue' })}>안녕하세요</div>
```

**"배경 채워진 버튼이면 글자는 흰색"** 같은 조합 요구는 `compoundVariants`로 — variant 조합에 따라 스타일 추가:

```javascript
export const button = recipe({
  base: { borderRadius: 6, outline: 'solid' },
  variants: {
    color: {
      orange: { color: 'orange', outlineColor: 'orange' },
      blue: { color: 'blue', outlineColor: 'blue' },
    },
    fill: { true: { color: 'white' } },
  },
  // 여러 variant가 동시에 켜졌을 때 적용
  compoundVariants: [
    { variants: { color: 'orange', fill: true }, style: { backgroundColor: 'orange' } },
    { variants: { color: 'blue', fill: true }, style: { backgroundColor: 'blue' } },
  ],
  defaultVariants: { color: 'blue', fill: false },
});

<div className={button({ color: 'orange', fill: true })}>안녕하세요</div>
```

`recipe` 덕에 분기 처리가 깔끔해진다. 안 그랬으면 복잡한 조건 분기가 됐을 것.

### 📌 정리
`런타임 계산을 없앤 type-safe CSS-in-JS = Vanilla Extract`

#### 핵심
> styled-component/emotion 같은 **런타임 CSS-in-JS**는 리렌더마다 스타일을 계산·삽입해 성능이 떨어진다. **Vanilla Extract**는 빌드타임에 .ts를 .css로 뽑는 **Zero-runtime** 방식(= CSS Modules-in-TypeScript)이라 런타임 비용이 없고 type-safe하다. `style`(기본)·`createTheme`(테마, `[themeClass, vars]` 반환)·`Sprinkles`(Tailwind식 Atomic)·`Recipes`(Stitches식 variant)로 거의 모든 CSS-in-JS 패턴을 커버한다.

#### ⭐️ 앞으로 기억할 것
- 1. **런타임 vs 빌드타임의 차이가 성능의 핵심**
  런타임 방식은 리렌더 = 함수 재실행 = 스타일 재계산/삽입. Vanilla Extract는 빌드타임에 .css로 끝내서 런타임 계산 0.
  ```text
  styled-component  →  런타임에 insertRule로 CSSOM 삽입 (리렌더마다)
  Vanilla Extract   →  빌드타임에 .ts → .css (sass처럼)
  ```
- 2. **`*.css.ts` 파일 + 번들러 설정 필수**
  빌드타임 변환이라 번들러 integration 없으면 동작 안 함.
- 3. **`createTheme`은 `[themeClass, vars]` 두 개를 준다**
  `themeClass` = 실제 값 박힌 className(상위 div에), `vars` = 변수 스키마(style에서 참조). 테마 전환은 상위 className만 토글.
  ```javascript
  const [themeClass, vars] = createTheme({...});      // 형태 + 기본값
  const otherTheme = createTheme(vars, {...});         // 같은 형태, 다른 값
  ```
- 4. **숫자 단위는 자동 px / 스타일 합성은 `style([a, b])`**
  `padding: 10` → `10px`. 합성 시 className이 합쳐져 출력.
- 5. **Sprinkles = Tailwind식 Atomic, Recipes = Stitches식 variant**
  - 짧은 atomic 클래스 원하면 Sprinkles(`createSprinkles`)
  - 컴포넌트 변형(color/size 등) 묶으려면 Recipes(`recipe` + `variants`)
  - 변형 조합별 스타일은 `compoundVariants`, 기본값은 `defaultVariants`
- 6. **장점: type-safe + 거추장스러운 문법 제거**
  styled-component의 `(props) => props.theme.color` 같은 문법 없이 객체로 깔끔하게. 잘못된 프로퍼티는 타입 검사로 잡힘.

📌 결론
▎ Vanilla Extract = "성능(zero-runtime) + 타입 안전 + 객체 기반 깔끔한 문법"을 한 번에.
▎ Sprinkles(Tailwind)·Recipes(Stitches)·dynamic(Linaria)로 주요 CSS-in-JS 패턴을 거의 총망라.
▎ ⭐️ 실무 적용 포인트
▎ → 런타임 CSS-in-JS 오버헤드가 걱정되거나, 여러 CSS-in-JS 개념을 한 번에 학습하고 싶을 때 추천.
▎ → 디자인 토큰/테마가 많은 프로젝트면 createTheme + vars 스키마로 다크모드·브랜드 테마를 className 토글로 처리.
▎ → 반복되는 컴포넌트 변형(버튼 color/size 등)은 recipe로 분기 정리.
