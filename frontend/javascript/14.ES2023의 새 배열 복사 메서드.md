# ES2023의 새 배열 복사 메서드 — toSorted / toReversed / toSpliced / with

> **원문**: https://www.sonarsource.com/blog/es2023-new-array-copying-methods-javascript/
> **번역 출처**: https://velog.io/@eunbinn/es2023-new-array-copying-methods-javascript

![post-thumbnail](https://velog.velcdn.com/images/eunbinn/post/1db97b15-37a6-4cda-8bae-f735c41166c7/image.webp)

`sort` 했더니 원본이 같이 바뀌어서 당황했던 경험, 리액트에서 배열 state 업데이트할 때 복사 안 해서 리렌더 안 됐던 경험… 다 `mutating 메서드` 때문이다. ES2023이 이걸 깔끔하게 해결하는 "복사본을 반환하는" 메서드 4개를 추가했길래 정리해둔다.

### 변경(mutation)과 사이드 이펙트

배열 메서드는 두 부류로 나뉜다.

- **원본을 변경(mutate)**: `sort`, `reverse`, `splice`
- **복사본을 반환**: `concat`, `map`, `filter`

문제는 앞쪽이다. 원본을 바꿔버리면 예상 못 한 사이드 이펙트가 생긴다.

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const reversed = languages.reverse();
console.log(reversed);
// => [ 'CoffeeScript', 'TypeScript', 'JavaScript' ]
console.log(languages);
// => [ 'CoffeeScript', 'TypeScript', 'JavaScript' ]  ← 원본도 같이 뒤집힘!
console.log(Object.is(languages, reversed));
// => true  ← 둘이 같은 배열을 가리킴
```

새 변수에 담았는데도 둘이 **같은 배열**을 가리킨다. 이게 함정.

#### 배열 변경과 리액트

가장 유명한 사고 지점이 리액트다. 배열을 변경한 뒤 그대로 새 state로 넣으면, **같은 객체 참조**라서 리렌더링이 안 일어난다. 그래서 리액트 문서엔 "배열 state는 복사 후 변경하라"는 페이지가 따로 있을 정도다.

#### 기존 해결법: 먼저 복사하고, 그다음 변경

`Array.from`, 스프레드(`...`), 인수 없는 `slice()` 등으로 먼저 복사본을 만든 뒤 변경하면 된다.

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const reversed = Array.from(languages).reverse();
// => [ 'CoffeeScript', 'TypeScript', 'JavaScript' ]
console.log(languages);
// => [ 'JavaScript', 'TypeScript', 'CoffeeScript' ]  ← 원본 유지!
console.log(Object.is(languages, reversed));
// => false
```

되긴 되는데, "변경 전에 복사부터 해야 한다"는 걸 매번 기억해야 한다는 게 불편하다. 그래서 ES2023이 나섰다.

### 새 메서드는 "복사하면서 변경"한다

`toSorted`, `toReversed`, `toSpliced`, `with` — 이 4개는 원본을 복사 → 복사본을 변경 → 반환한다. 함수 하나만 호출하면 되니 작성도 쉽고, 원본 보존이 보장되니 읽기도 쉽다.

#### `Array.prototype.toSorted`

정렬된 **새 배열**을 반환. 원본은 그대로.

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const sorted = languages.toSorted();
console.log(sorted);
// => [ 'CoffeeScript', 'JavaScript', 'TypeScript' ]
console.log(languages);
// => [ 'JavaScript', 'TypeScript', 'CoffeeScript' ]  ← 원본 유지
```

⚠️ 단, `sort`의 고질병은 그대로 물려받는다. 숫자나 악센트 문자는 비교 함수를 직접 줘야 한다.

```javascript
const numbers = [5, 3, 10, 7, 1];
const sorted = numbers.toSorted();
console.log(sorted);
// => [ 1, 10, 3, 5, 7 ]  ← ❌ 문자열로 비교돼서 10이 앞으로
const sortedCorrectly = numbers.toSorted((a, b) => a - b);
console.log(sortedCorrectly);
// => [ 1, 3, 5, 7, 10 ]  ← ✅

const strings = ["abc", "äbc", "def"];
const sorted = strings.toSorted();
console.log(sorted);
// => [ 'abc', 'def', 'äbc' ]  ← ❌ 악센트 문자가 뒤로
const sortedCorrectly = strings.toSorted((a, b) => a.localeCompare(b));
console.log(sortedCorrectly);
// => [ 'abc', 'äbc', 'def' ]  ← ✅
```

#### `Array.prototype.toReversed`

순서를 뒤집은 새 배열 반환.

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const reversed = languages.toReversed();
console.log(reversed);
// => [ 'CoffeeScript', 'TypeScript', 'JavaScript' ]
```

`reverse()` 결과를 새 변수에 담는 건 원본도 같이 바뀌어서 버그 소지가 있다(Sonar 같은 린터가 잡아주는 패턴). 이제 복사+변경 대신 `toReversed`/`toSorted`를 쓰면 된다.

#### `Array.prototype.toSpliced`

`splice`와 미묘하게 다르다.

| | 반환값 | 원본 |
|---|---|---|
| `splice` | **삭제된** 요소들의 배열 | 변경됨 |
| `toSpliced` | **변경 적용된 전체** 새 배열 | 유지 |

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const spliced = languages.toSpliced(2, 1, "Dart", "WebAssembly");
console.log(spliced);
// => [ 'JavaScript', 'TypeScript', 'Dart', 'WebAssembly' ]
```

즉 "삭제된 요소"가 필요하면 `toSpliced`만으론 안 된다. 원본에 `slice`를 따로 적용해야 한다. (주의: `splice`는 `(인덱스, 삭제개수)`, `slice`는 `(시작, 끝)`으로 인수가 다름.)

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const startDeletingAt = 2;
const deleteCount = 1;
const spliced = languages.toSpliced(
  startDeletingAt,
  deleteCount,
  "Dart",
  "WebAssembly"
);
const removed = languages.slice(startDeletingAt, startDeletingAt + deleteCount);
console.log(spliced);
// => [ 'JavaScript', 'TypeScript', 'Dart', 'WebAssembly' ]
console.log(removed);
// => [ 'CoffeeScript' ]
```

#### `Array.prototype.with`

`arr[i] = value` 대입의 **복사 버전**이다. 인덱스 하나를 바꾼 새 배열을 반환.

❌ 직접 변경:

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
languages[2] = "WebAssembly";
console.log(languages);
// => [ 'JavaScript', 'TypeScript', 'WebAssembly' ]  ← 원본 변경됨
```

✅ 복사하면서 변경:

```javascript
const languages = ["JavaScript", "TypeScript", "CoffeeScript"];
const updated = languages.with(2, "WebAssembly");
console.log(updated);
// => [ 'JavaScript', 'TypeScript', 'WebAssembly' ]
console.log(languages);
// => [ 'JavaScript', 'TypeScript', 'CoffeeScript' ]  ← 원본 유지
```

### 배열만이 아니다 — TypedArray도 된다

`Int8Array`부터 `BigUint64Array`까지 모든 `TypedArray`에서 `toSorted`, `toReversed`, `with`를 쓸 수 있다. 단 `TypedArray`엔 `splice`가 없어서 `toSpliced`는 못 쓴다.

### 주의: Array 상속 클래스에서는 일반 Array를 반환

`map`/`filter`/`concat`은 서브클래스 인스턴스를 그대로 반환하지만, **새 복사 메서드들은 일반 `Array`로 떨어뜨린다.**

```javascript
class MyArray extends Array {}
const languages = new MyArray("JavaScript", "TypeScript", "CoffeeScript");

const upcase = languages.map((language) => language.toUpperCase());
console.log(upcase instanceof MyArray);   // => true

const reversed = languages.toReversed();
console.log(reversed instanceof MyArray); // => false  ← 일반 Array가 됨
```

다시 커스텀 타입으로 되돌리려면 `MyArray.from`으로 감싼다.

```javascript
class MyArray extends Array {}
const languages = new MyArray("JavaScript", "TypeScript", "CoffeeScript");
const reversed = MyArray.from(languages.toReversed());
console.log(reversed instanceof MyArray); // => true
```

### 지원 현황

Chrome 110, Safari 16.3, Node.js 20, Deno 1.31 부터 4개 메서드 전부 지원. 아직 안 되는 환경엔 폴리필/shim도 있다.

### 📌 정리
`ES2023 복사 메서드 = 원본 안 건드리고 변경된 새 배열을 돌려준다`

#### 핵심
> `sort`/`reverse`/`splice`는 원본을 변경(mutate)해서 사이드 이펙트와 리액트 리렌더 누락을 일으킨다. ES2023의 `toSorted`/`toReversed`/`toSpliced`/`with`는 복사본을 변경해 반환하므로 "먼저 복사" 단계가 필요 없다. 단 `toSpliced`는 삭제 요소가 아니라 변경된 전체 배열을 반환하고, Array 서브클래스에서는 일반 Array로 떨어진다.

#### ⭐️ 앞으로 기억할 것
- 1. mutating ↔ copying 짝으로 외우기
  `sort→toSorted`, `reverse→toReversed`, `splice→toSpliced`, `arr[i]=x → with(i, x)`.
  ```javascript
  const next = arr.with(2, "WebAssembly"); // 원본 보존
  ```
- 2. 리액트 state에 딱
  복사 안 해서 리렌더 누락되던 문제를 한 줄로 해결.
  ```javascript
  setItems(items.toSorted((a, b) => a - b));
  ```
- 3. `toSorted`도 비교 함수는 필요
  숫자·악센트 문자는 `(a,b)=>a-b`, `localeCompare`로 직접 비교해야 한다.
- 4. `toSpliced`는 반환값이 다르다
  `splice`는 삭제된 요소를, `toSpliced`는 변경된 전체 배열을 반환. 삭제 요소가 필요하면 `slice` 따로.
- 5. 서브클래스는 일반 Array로 떨어진다
  `class extends Array`에서 복사 메서드 쓰면 `instanceof` 깨짐 → `MyArray.from(...)`으로 복구.

📌 결론
▎ "변경 메서드는 위험하다"는 옛 상식을, 언어 차원에서 안전한 짝으로 대체했다.
▎ 리액트·불변성(immutability) 코드에서 `Array.from(arr).sort()` 같은 보일러플레이트가 사라진다.
▎ ⭐️ 실무 적용 포인트: 타깃 런타임(Chrome 110+/Node 20+)만 확인되면 state 업데이트는 전부 `to*`/`with`로 갈아타도 된다. 안 되는 환경은 폴리필.
