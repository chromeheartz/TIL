# 자바스크립트의 진짜 새로운 변화 (ES2025 / ES2026)

> **원문**: https://neciudan.dev (What's new in JavaScript)
> **번역 출처**: https://velog.io/@superlipbalm/whats-new-in-javascript (김찬희 번역)

매년 ES 신문법 나온다는 얘긴 듣는데, 솔직히 "그래서 지금 쓸 수 있는 건가?"가 항상 헷갈렸다. async/await 이후로 체감되는 변화가 없다고 느꼈는데, 사실 그 사이에 조용히 쌓인 게 꽤 된다. 이 글은 **ES2025 확정분 / ES2026 추가분 / 아직 표준 안 된 것들**을 나눠서 정리한다.

### ES2025 — 이미 확정된 것들

#### Iterator Helpers — 배열로 변환하지 않고 바로 체이닝

지금까진 `querySelectorAll` 결과 같은 이터러블에 `.filter()`, `.map()` 쓰려면 일단 `Array.from`으로 통째로 배열을 만들어야 했다. 데이터가 크면 중간 배열이 메모리에 다 올라간다. `Iterator.from`은 lazy 평가라서 필요한 만큼만 흘려보낸다.

```javascript
// ❌ 일단 전부 배열로 만들고 시작
const visibleCards = Array.from(document.querySelectorAll('.card'))
  .filter(el => !el.classList.contains('hidden'))
  .map(el => el.dataset.id);

// ✅ 이터레이터 위에서 바로, 마지막에만 toArray()
const visibleCards = Iterator.from(document.querySelectorAll('.card'))
  .filter(el => !el.classList.contains('hidden'))
  .map(el => el.dataset.id)
  .toArray();
```

무한 시퀀스나 스트림 다룰 때 `.take()`까지 붙이면 진가가 나온다.

#### Set Methods — 집합 연산이 드디어 표준

교집합/합집합 구하려고 `filter` + `includes` 돌리던 거, 이제 메서드로 끝난다.

```javascript
frontEnd.union(backEnd);               // 합집합
frontEnd.intersection(backEnd);        // 교집합
frontEnd.difference(backEnd);          // 차집합
frontEnd.symmetricDifference(backEnd); // 대칭 차집합 (둘 중 한쪽에만)
```

#### JSON Modules — import로 JSON 직접 가져오기

`with { type: 'json' }`가 핵심. 타입을 명시적으로 안 적으면 안 불러와진다. 서버가 JSON인 척 JS를 내려주는 공격을 막는 안전장치다.

```javascript
import config from './config.json' with { type: 'json' };

const translations = await import('./translations.json', {
  with: { type: 'json' }
});
```

#### Promise.try — sync일지 async일지 모르는 함수 안전하게 감싸기

서드파티 함수가 동기로 throw할 수도, Promise를 reject할 수도 있을 때. 예전엔 `try/catch`랑 `.catch()`를 둘 다 깔아야 했는데 이걸로 하나의 체인으로 통일된다.

```javascript
Promise.try(() => thirdParty.doThing())
  .then(result => processResult(result))
  .catch(err => handleAnyFailure(err)); // 동기 throw든 비동기 reject든 여기로
```

#### RegExp.escape — 사용자 입력을 정규식에 안전하게

검색어에 `.`이나 `*` 들어가면 정규식이 엉뚱하게 동작한다. 이제 이스케이프를 직접 짤 필요 없다.

```javascript
const userInput = 'file.txt';
const pattern = new RegExp(RegExp.escape(userInput)); // .을 리터럴로 처리
```

#### Float16Array — 16비트 부동소수점 배열

GPU / AI 연산에서 메모리 아끼려고 half-precision 쓸 때. 평소 앱 개발에선 만날 일 거의 없지만, WebGPU 쪽 하면 반갑다.

### ES2026 — 새로 들어온 것들

#### Math.sumPrecise — 부동소수점 누적 오차 해결

`0.1`을 10000번 더하면 `1000`이 안 나오는 그 문제. Shewchuk 알고리즘으로 정확히 계산한다. 돈 계산할 때 특히.

```javascript
const cents = Array(10000).fill(0.1);
Math.sumPrecise(cents);             // 1000  (그냥 reduce 하면 1000.0000...2)
Math.sumPrecise([1e20, 1, -1e20]);  // 1     (자릿수 차이 커도 안 날아감)
```

#### Uint8Array base64 / hex 변환

바이트 배열 ↔ base64/hex 변환을 라이브러리 없이. 그동안 이게 왜 없었나 싶었던 것 중 하나.

```javascript
const bytes = new Uint8Array([72, 101, 108, 108, 111]);
bytes.toBase64();   // "SGVsbG8="
bytes.toHex();      // "48656c6c6f"
Uint8Array.fromBase64("SGVsbG8=");
Uint8Array.fromHex("48656c6c6f");
```

#### Error.isError — realm 경계 넘어서도 Error 판별

`instanceof Error`는 iframe / worker처럼 realm이 다르면 false가 나온다. `Error.isError`는 그런 거 신경 안 쓰고 안정적으로 판별.

```javascript
if (Error.isError(maybeError)) {
  logger.error(maybeError.message);
}
```

#### Iterator.concat — 여러 이터레이터 이어붙이기

```javascript
const all = Iterator.concat(first(), second());
for (const n of all) console.log(n);
```

#### Map.getOrInsert — 캐시 패턴 한 줄로

"있으면 가져오고 없으면 기본값 넣기"를 `if (!map.has(k)) map.set(...)` 없이.

```javascript
// 단어 카운트
counts.set(word, counts.getOrInsert(word, 0) + 1);

// 무거운 계산은 getOrInsertComputed로 지연 실행
cache.getOrInsertComputed(id, () => expensiveDatabaseLookup(id));
```

> `getOrInsert(key, value)`는 값을 바로, `getOrInsertComputed(key, fn)`는 없을 때만 함수 실행. 캐시 미스일 때만 비싼 작업 돌고 싶으면 후자.

#### Array.fromAsync — async 이터러블 모으기

페이지네이션 fetch 같은 async generator 결과를 배열로.

```javascript
const allItems = await Array.fromAsync(fetchPages());
```

#### JSON.parse reviver에 source context 추가

큰 정수가 `JSON.parse` 거치면서 정밀도 깨지는 문제. 이제 reviver 세 번째 인자 `context.source`로 원본 문자열에 접근해서 `BigInt`로 살릴 수 있다.

```javascript
const parsed = JSON.parse(text, (key, value, context) => {
  if (typeof value === 'number' && !Number.isSafeInteger(value)) {
    return BigInt(context.source); // 원본 문자열에서 직접 BigInt로
  }
  return value;
});
```

### 아직 표준은 아니지만 곧 오는 것들

#### Temporal API — Date를 드디어 대체 (Stage 4)

JS `Date`의 그 악명 높은 설계(가변, 타임존 지옥, 월이 0부터)를 갈아엎는다. 불변 타입 + 타임존 일급 지원.

```javascript
// 타임존 포함 시각
const meeting = Temporal.ZonedDateTime.from(
  '2026-04-23T09:00[Australia/Sydney]'
);
const inLondon = meeting.withTimeZone('Europe/London'); // 변환 한 줄

// 날짜만 다루기 + 나이 계산
const birthday = Temporal.PlainDate.from('1993-10-26');
const today = Temporal.Now.plainDateISO();
const age = today.since(birthday, { largestUnit: 'years' });
```

#### using 키워드 — 자동 리소스 정리 (Stage 3)

파일 핸들, DB 트랜잭션처럼 "다 쓰면 닫아야 하는" 것들. 스코프 벗어나면 자동으로 정리된다. `try/finally` 안 써도 됨.

```javascript
async function transferMoney(from, to, amount) {
  await using tx = await db.beginTransaction(); // 스코프 끝나면 자동 정리
  await tx.debit(from, amount);
  await tx.credit(to, amount);
  await tx.commit();
}
```

#### import defer — 모듈 평가 지연 (Stage 3)

무겁지만 자주 안 쓰는 모듈을, 실제로 프로퍼티에 접근할 때까지 평가를 미룬다. 앱 시작 속도에 유리.

```javascript
import defer * as heavyModule from './heavy.js';

function rarelyCalled() {
  return heavyModule.doExpensiveThing(); // 여기서 처음으로 평가됨
}
```

### 📌 보너스: AI 코딩 도구에 "모던 JS 써라" 규칙 심기

원문에서 제일 실용적이라 느낀 부분. Cursor / Copilot 룰에 이걸 넣어두면 레거시 대신 신문법을 제안해준다.

```markdown
# Modern JavaScript preferences (ES2025/ES2026)
오래된 API 대신 새 API를 우선 제안할 것.

## 이터레이터 / 컬렉션
- 크거나 무한한 시퀀스 → 배열 변환 말고 Iterator.prototype 메서드
- 집합 연산 → intersection() / union() / difference()
- 개수 세기 → map.getOrInsert(key, default)

## 날짜/시간
- 복잡한 날짜 연산 → Temporal API
- 신규 코드에 moment.js / date-fns 쓰지 말 것

## Promise
- sync일지 async일지 모르는 함수 → Promise.try(() => fn())

## 리소스 정리
- 정리 필요한 리소스 → using handle = openResource()
- 정리 목적의 try/finally 쓰지 말 것

## 에러
- Error 판별 → Error.isError(x) (instanceof는 realm 넘으면 불안정)

## 숫자
- float 합산 → Math.sumPrecise(values)
- 바이트 인코딩 → bytes.toBase64() / bytes.toHex()

## 모듈
- JSON import → import data from './data.json' with { type: 'json' }
- 크고 잘 안 쓰는 모듈 → import defer * as heavy from './heavy.js'
```

### 📌 정리

`async/await 이후에도 JS는 조용히 계속 좋아지고 있었다`

#### 핵심

> ES2025는 **이터레이터/집합/JSON import/Promise.try**로 매일 쓰는 코드의 군더더기를 걷어냈고, ES2026은 **숫자 정밀도·인코딩·realm 안전성** 같은 구멍을 메웠다. 그리고 **Temporal / using / import defer**가 곧 들어오면서 Date 지옥과 try/finally가 끝난다. 핵심은 "라이브러리로 때우던 걸 표준이 흡수하는 중"이라는 흐름.

#### ⭐️ 앞으로 기억할 것

- 1. 큰 컬렉션은 `Array.from` 말고 `Iterator.from`
  중간 배열 안 만들고 lazy하게 흐른다. 마지막에만 `.toArray()`.
  ```javascript
  Iterator.from(nodeList).filter(...).map(...).toArray();
  ```
- 2. sync/async 섞인 함수는 `Promise.try`
  동기 throw와 비동기 reject를 한 `.catch()`로 통일.
  ```javascript
  Promise.try(() => maybeAsyncFn()).catch(handle);
  ```
- 3. 캐시/카운터는 `getOrInsert` 계열
  비싼 계산이면 `getOrInsertComputed`로 미스일 때만 실행.
  ```javascript
  cache.getOrInsertComputed(id, () => fetchFromDB(id));
  ```
- 4. Error 판별은 `Error.isError`, `instanceof` 아님
  iframe/worker 경계 넘으면 instanceof가 거짓말함.
- 5. 돈/누적 합은 `Math.sumPrecise`
  `0.1` 만 번 더해도 정확히 `1000`.
- 6. 사용자 입력 → 정규식이면 무조건 `RegExp.escape`
  안 하면 `.` `*` 때문에 매칭이 깨지거나 ReDoS 위험.

📌 결론

▎ ES2025/2026은 화려한 신문법보다 "당연했어야 할 기본기"를 채운 업데이트다.
▎ Temporal·using·import defer는 아직 표준 전이지만 Stage 3~4라 곧 온다 — 미리 익혀둘 가치 있음.
▎ ⭐️ 실무 적용 포인트: 당장 폴리필/트랜스파일 없이 쓰긴 이르지만, **AI 룰셋에 모던 JS 규칙을 박아두면** 새 코드가 자연스럽게 신문법 쪽으로 수렴한다. date 라이브러리 신규 도입은 이제 한 번 더 고민하자(Temporal 대기).
