# 베이스라인으로 불필요한 JS 걷어내기

> **원문**: [How Baseline Can Help You Ship Less JavaScript][ref-1] — Jad Joubran (Smashing Magazine, 2026.08.07)
> **번역 출처**: [베이스라인으로 불필요한 자바스크립트 줄이기][ref-2] — 조영제

`npm audit`은 주기적으로 돌리면서 "이 라이브러리, 아직도 브라우저가 못 하는 일 하고 있나?"는 한 번도 안 물어봤다는 문장에서 뜨끔했다. 설치할 땐 필요했는데 그 사이 브라우저에 들어와버린 기능들을 **묶음 단위로 점검하는 방법**을 정리해둠.

![package.json에서 제거된 npm 의존성 git diff](https://files.smashing.media/articles/how-baseline-can-help-ship-less-javascript/1-git-diff-removed-npm-dependencies.png)

글쓴이 계산으로는 중간 규모 앱 기준 **gzip 60~90KB** 정도가 이미 플랫폼이 대신할 수 있는 의존성이라고 한다. 날짜/숫자 포매팅, HTTP, 모달, 툴팁, 깊은 복사, 그룹화… 몇 년 전엔 진짜 없던 것들이다.

### 베이스라인(Baseline) 3단계

[`WebDX 커뮤니티 그룹`][ref-3]이 관리하는 지표로, 크롬·엣지·파이어폭스·사파리 전반에서 "이 기능 써도 되나?"를 쉬운 말로 알려준다.

| 상태 | 의미 | 라이브러리 걷어내기 |
|------|------|------|
| Limited availability | 아직 주요 엔진 전부에 없음 | ❌ 폴백 없이 쓰면 위험 |
| Newly available | 주요 엔진 전부에 막 들어감 | 🤔 사용자층 확인 or 기능 감지 필요 |
| Widely available | 전부 들어가고 **30개월** 지남 | ✅ 그냥 교체 |

이 30개월 간격이 핵심이다. "베이스라인이다"라고 뭉뚱그리지 말고 **Newly냐 Widely냐**를 구분해서 판단해야 한다.

확인하는 곳은 세 군데:
- [`webstatus.dev`][ref-4]
- [`MDN`][ref-5] 레퍼런스 페이지 상단의 베이스라인 배지
- `web-features` npm 패키지 (코드로 조회)

### 지우기 전에 던질 질문 3개

"브라우저가 해준대!" 하고 바로 뜯어내면 안 된다. 이 세 개가 글 전체를 관통하는 판단 기준이다.

#### 1. 내 사용자층에게 안전한가?
추상적인 "베이스라인인가"가 아니라 **내 앱 사용자 기준**. 최신 브라우저만 쓰는 B2B 대시보드랑 구형 안드로이드가 꼬리처럼 붙은 공개 사이트는 답이 다르다. Newly available이면 애널리틱스나 `browserslist`로 확인.

#### 2. 교체 비용이 진짜 얼마인가?
폴리필이 필요하고, 그 폴리필이 원래 라이브러리보다 무거우면 번들이 오히려 **커진다**. (뒤에 Temporal이 딱 이 케이스)

#### 3. 내가 쓰는 기능을 전부 커버하는가?
라이브러리는 대체로 플랫폼 기능보다 많은 걸 한다. axios 인터셉터를 쓰고 있다면 `fetch`로 바꾸는 순간 그걸 직접 짜야 한다.

### 묶음 1. 국제화 — 제일 쉬운 성과

`Intl` 네임스페이스가 소형 포매팅 라이브러리들을 거의 다 대체한다.

| 라이브러리 (gzip) | 대체 |
|------|------|
| `timeago.js` (1KB) | `Intl.RelativeTimeFormat` |
| `pluralize` (2.3KB) | `Intl.PluralRules` |
| `numeral` (3.9KB) | `Intl.NumberFormat` |
| `humanize-duration` (6.6KB) | `Intl.DurationFormat` |
| 배열 이어붙이기 헬퍼 | `Intl.ListFormat` |

#### 상대 시간
```js
const rtf = new Intl.RelativeTimeFormat('ko', { numeric: 'auto' })

rtf.format(-1, 'day')   // "어제"  ← numeric: 'auto' 덕분에 "1일 전"이 아니라 "어제"
rtf.format(2, 'hour')   // "2시간 후"
```

timeago.js랑 다른 점 하나: **단위를 알아서 골라주진 않는다.** 두 시각 차이를 구해서 초/분/시/일 중 맞는 단위를 고르는 건 직접 해야 한다. 근데 이거 몇 줄짜리 헬퍼라 한 번 짜두면 끝.

```js
// 차이(초)를 보고 가장 큰 단위를 골라주는 헬퍼
const UNITS = [
  ['year', 60 * 60 * 24 * 365],
  ['month', 60 * 60 * 24 * 30],
  ['day', 60 * 60 * 24],
  ['hour', 60 * 60],
  ['minute', 60],
  ['second', 1],
]

function timeAgo(date, locale = 'ko') {
  const diffSec = (date.getTime() - Date.now()) / 1000
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' })
  const [unit, sec] = UNITS.find(([, s]) => Math.abs(diffSec) >= s) ?? UNITS.at(-1)
  return rtf.format(Math.round(diffSec / sec), unit)
}
```

#### 숫자·통화·리스트
```js
new Intl.NumberFormat('ko-KR').format(9876543)                                  // "9,876,543"
new Intl.NumberFormat('ko-KR', { style: 'currency', currency: 'KRW' }).format(15000) // "₩15,000"
new Intl.NumberFormat('ko', { notation: 'compact' }).format(34000)              // "3.4만"

new Intl.ListFormat('ko', { type: 'conjunction' }).format(['사과', '배', '감'])
// "사과, 배 및 감"
```

#### 기간 — ⚠️ 아직 Newly available
```js
new Intl.DurationFormat('ko', { style: 'long' }).format({ hours: 2, minutes: 15 })
// "2시간 15분"
```
`Intl.DurationFormat`은 2025년 3월에 주요 엔진에 다 들어갔고 Widely는 2027년 예상. 사내 도구면 지금 써도 되고, 공개 사이트면 1년 더 기다리거나 폴백을 둔다.

> 이 묶음 전체(humanize-duration, timeago.js, pluralize, numeral) 걷어내면 **약 14KB**

### 묶음 2. HTTP 클라이언트

`axios`(17KB), `superagent`(19KB) → `fetch` + `AbortController`. 둘 다 Widely available.

```js
// ❌ axios가 암묵적으로 해주던 것
const { data } = await axios.get('/api/posts', { timeout: 3000 })

// ✅ fetch는 전부 명시적으로
const res = await fetch('/api/posts', { signal: AbortSignal.timeout(3000) })
const data = await res.json()
```

`res.json()` 한 줄 늘어나는 게 이 묶음의 성격을 보여준다. **fetch는 기본으로 덜 해주고, 나머지는 내가 고른다.**

#### fetch가 axios를 대신 못 하는 곳 (질문 3번이 제일 빡센 구간)

| 기능 | axios | fetch |
|------|------|------|
| HTTP 에러(4xx/5xx) | reject | **resolve됨** → `res.ok` 직접 확인 |
| 인터셉터 (토큰 주입, 401 일괄 처리) | ✅ | ❌ 래퍼 함수/클래스 필요 |
| 자동 재시도 | 플러그인으로 ✅ | ❌ 직접 구현 |
| 업로드 진행률 | ✅ | ❌ 아직 일급 지원 없음 |

솔직히 404가 resolve되는 건 아직도 가끔 잊는다. 글쓴이도 인터셉터가 필요해서 수년간 `fetch` 위에 커스텀 클래스를 얹어 썼다고 한다. 결국 **평범한 GET/POST만 쓰면 얇은 래퍼로 17KB 절약**, 업로드 진행률 바가 있으면 라이브러리 유지가 맞다.

```js
// 최소한의 fetch 래퍼 — 에러 reject + 토큰 주입만
async function api(path, options = {}) {
  const res = await fetch(path, {
    ...options,
    headers: { Authorization: `Bearer ${getToken()}`, ...options.headers },
  })
  if (!res.ok) throw new Error(`HTTP ${res.status}`)
  return res.json()
}
```

### 묶음 3. UI 프리미티브 — 교체 명분이 제일 확실

플랫폼 기능이 따라잡은 수준이 아니라 **직접 만든 것보다 접근성이 더 좋다.**

| 라이브러리 (gzip) | 대체 |
|------|------|
| `a11y-dialog` (1.8KB) | `<dialog>` |
| `focus-trap` (6.6KB) | `<dialog>` + `showModal()` |
| `body-scroll-lock` (1.3KB) | CSS `:has()` + `:modal` |
| `tippy.js` (14KB, Popper 포함) | Popover API + CSS 앵커 포지셔닝 |

#### `<dialog>`
모달 라이브러리 코드 대부분은 사실 접근성 처리용이다. `showModal()` 하나로 다 된다.

```html
<dialog id="logout">
  <form method="dialog">
    <p>로그아웃할까요?</p>
    <button value="no">취소</button>
    <button value="yes">로그아웃</button>
  </form>
</dialog>
```

```js
const dialog = document.getElementById('logout')

// 포커스 안으로 이동 + 배경 inert + Escape 닫기 + 닫힐 때 포커스 복귀 + top layer 렌더링
dialog.showModal()

dialog.addEventListener('close', () => {
  if (dialog.returnValue === 'yes') logout()
})
```

top layer에 올라가니까 `z-index` 싸움도 없고, 오버레이는 `::backdrop`으로 스타일링.

배경 스크롤 잠금만 `<dialog>`가 안 해주는데, 이건 CSS 한 줄이다.

```css
/* ❌ dialog[open] — show()로 열어도(비모달) 붙어서 스크롤이 잠겨버림 */
body:has(dialog[open]) { overflow: hidden; }

/* ✅ :modal — showModal()로 열었을 때만 true */
body:has(dialog:modal) { overflow: hidden; }
```

라이브러리 3개 → 요소 하나 + CSS 한 줄. 하하.

#### Popover API + 앵커 포지셔닝
드롭다운, 툴팁 같은 비모달 떠 있는 패널은 Popover API. JS 없이 토글, 바깥 클릭 닫기, Escape 닫기, top layer까지.

```html
<button popovertarget="profile-menu" id="profile-btn">내 계정</button>

<div popover id="profile-menu">
  <a href="/settings">설정</a>
  <a href="/logout">로그아웃</a>
</div>
```

툴팁 라이브러리의 나머지 절반인 **위치 계산**(Popper가 하던 일)은 CSS 앵커 포지셔닝으로.

```css
#profile-btn {
  anchor-name: --profile;
}

#profile-menu {
  position-anchor: --profile;
  position-area: bottom;  /* 버튼 바로 아래에 붙음 */
  margin: 0;
}
```

| 속성 | 설명 |
|------|------|
| `anchor-name` | 기준(앵커)이 될 요소에 이름 붙이기 (`--` 접두사) |
| `position-anchor` | 떠 있는 요소가 어떤 앵커를 따라갈지 지정 |
| `position-area` | 앵커 기준 어느 방향에 놓을지 (`top`, `bottom` 등) |
| `position-try` | 뷰포트 넘칠 때 대체 위치 — 버전별 지원 편차 있음 |

⚠️ 지원 상태가 제각각이다.
- Popover API: Newly available (2025.01~)
- 앵커 포지셔닝: Newly available (2026.01, 파이어폭스 147이 마지막 퍼즐. 크롬 125+, 사파리 26+)

앵커 포지셔닝은 이 글에서 가장 최신이라 질문 1번에 정면으로 걸린다. 구형 브라우저용 폴백 위치는 남겨두자.

> UI 묶음 합계 **약 24KB** + 수제 구현보다 나은 접근성 기본값

### 묶음 4. Lodash 유틸리티

통째로 쓰는 경우(25KB)는 줄었지만 `lodash.clonedeep`, `lodash.groupby` 같은 개별 패키지는 여전히 흔하다.

#### 그룹화 — `Object.groupBy`
```js
const orders = [
  { id: 1, status: 'paid' },
  { id: 2, status: 'pending' },
  { id: 3, status: 'paid' },
]

Object.groupBy(orders, (o) => o.status)
// { paid: [{id:1}, {id:3}], pending: [{id:2}] }

// 키가 문자열이 아니면 Map.groupBy
Map.groupBy(orders, (o) => o.id > 1)
```
Newly available(2024.03~), Widely는 2026년 말 예상.

#### 깊은 복사 — `structuredClone` (Widely)
```js
const state = { createdAt: new Date(), tags: new Set(['fe']) }

// ❌ Date는 문자열로, Set은 {}로 망가짐
JSON.parse(JSON.stringify(state))

// ✅ Date, Map, Set, ArrayBuffer, 순환 참조까지 OK
structuredClone(state)
```

한계도 있다: **함수는 에러, DOM 노드 불가, 클래스 인스턴스는 프로토타입 날아감.** 순수 데이터 복사면 완벽한 대체품.

#### 집합 연산 — `Set` 메서드 (Newly, 2024.06~)
```js
const frontend = new Set(['kim', 'lee', 'park'])
const backend = new Set(['lee', 'choi'])

frontend.intersection(backend)  // Set {'lee'}
frontend.union(backend)         // Set {'kim', 'lee', 'park', 'choi'}
frontend.difference(backend)    // Set {'kim', 'park'}
```
그 외 `symmetricDifference`, `isSubsetOf`, `isSupersetOf`, `isDisjointFrom`.

#### 남겨도 되는 것
`debounce`, `throttle`은 아직 네이티브가 없다. `lodash.debounce` 개별 설치는 합리적. 요점은 "Lodash 지워라"가 아니라 **"브라우저가 이미 가진 걸 또 배포하지 마라"**.

> `clonedeep` + `groupby`만 걷어내도 **약 8KB**

### 묶음 5. Temporal — 아직 걷어내면 안 되는 사례

지금까지는 전부 "걷어내라"였는데 이건 반대. 그래서 오히려 제일 배울 게 많았다.

`Temporal`은 `Date`의 진짜 대체재다. 불변 객체, 일관된 타임존 처리, 월이 0부터 시작하는 그 악몽도 끝. 2026년 3월 TC39 스테이지 4, ES2026 포함. 파이어폭스 139, 크롬 144에는 들어갔지만 **사파리 정식 릴리스엔 아직 없음** → Limited availability.

숫자로 보면 명확하다.

| 선택지 | gzip |
|------|------|
| `dayjs` | 약 3KB |
| 경량 Temporal 폴리필 (BigInt 미사용) | 19KB |
| `@js-temporal/polyfill` (공식) | 약 44KB |

dayjs를 Temporal + 공식 폴리필로 바꾸면 3KB 아끼는 게 아니라 **41KB 늘어난다.**

세 질문에 넣어보면:
- 질문 1 (사용자층): ❌ 베이스라인 아님
- 질문 2 (비용): ❌ 폴리필이 원래 라이브러리의 10배 이상
- 질문 3 (기능): ✅ dayjs보다 낫다 — 근데 1, 2를 못 넘으니 의미 없음

결론: **지금은 `dayjs`/`date-fns` 유지.** 사파리가 싣고 베이스라인 되면 네이티브로 쓰고 구형 브라우저에만 폴리필 조건부 로드. 캘린더에 적어두고 몇 달 뒤 다시 볼 항목.

### 📌 5단계: 필요하면 점진적 향상으로 교체

Widely면 그냥 교체. Newly면 사용자층 확인 or 기능 감지 + 폴백.

```js
function formatDuration(duration) {
  if (typeof Intl.DurationFormat === 'function') {
    // ✅ 지원 브라우저: 플랫폼 기능
    return new Intl.DurationFormat('ko', { style: 'long' }).format(duration)
  }
  // 미지원: 단순 포맷으로 폴백 (또는 라이브러리 동적 import)
  return `${duration.hours ?? 0}시간 ${duration.minutes ?? 0}분`
}
```

지원하는 브라우저엔 코드를 덜 보내고, 못 하는 브라우저도 안 깨진다.

### 합계와 앞으로 볼 것

| 묶음 | 절약 (gzip) |
|------|------|
| 국제화 | 약 14KB |
| HTTP | 약 17KB |
| UI 프리미티브 | 약 24KB |
| Lodash | 8KB 이상 |
| **합계** | **60~90KB** (lodash 통째로 썼으면 더) |

압축 전 기준으로는 2~3배. 다이얼로그 패키지 중엔 단독으로 50KB 넘는 것도 있다고.

1년 안에 상태가 바뀔 것들:
- **Temporal** 사파리 탑재 → 날짜 라이브러리 + 폴리필 둘 다 제거 가능
- **CSS 앵커 포지셔닝** Widely 진입 → 툴팁/팝오버 위치 라이브러리 제거 안전
- **`Object.groupBy`, `Set` 메서드** 2026년 말 Widely → "사용자층 확인"에서 "그냥 쓰기"로

### 📌 정리
`의존성은 설치가 끝이 아니라 분기마다 다시 보는 것`

#### 핵심
> 브라우저는 계속 기능을 흡수하고 있어서, 예전에 필요했던 라이브러리 상당수가 이미 플랫폼에 들어와 있다.
> 걷어내기 전엔 **① 내 사용자층 기준 안전한가 ② 폴리필 포함 실제 비용 ③ 내가 쓰는 기능 전부 커버하나** 세 가지를 따진다.
> Widely available은 바로 교체, Newly available은 기능 감지 + 폴백, Limited는 (Temporal처럼) 대기.

#### ⭐️ 앞으로 기억할 것
- 1. "베이스라인이다" ≠ "지금 써도 된다"
Newly와 Widely 사이 30개월이 실제 판단 포인트. MDN 배지 볼 때 어느 쪽인지까지 확인하기.

- 2. 폴리필 무게까지 계산에 넣기
Temporal 사례처럼 네이티브가 더 좋은 API여도 폴리필 때문에 번들이 커질 수 있다. 교체 PR에 **before/after 번들 크기**를 같이 적는 습관.

- 3. `fetch`는 4xx/5xx에서 reject 안 한다
axios 걷어낼 때 제일 많이 터지는 부분. 래퍼에서 `res.ok` 체크는 필수.
```js
// ❌ 404여도 catch로 안 감
const data = await fetch(url).then((r) => r.json())

// ✅
const res = await fetch(url)
if (!res.ok) throw new Error(`HTTP ${res.status}`)
```

- 4. 모달은 `<dialog>` + `showModal()` 부터 생각
focus-trap, Escape, 포커스 복귀, z-index까지 해결. 스크롤 잠금은 `[open]` 말고 `:modal`.
```css
body:has(dialog:modal) { overflow: hidden; }
```

- 5. `structuredClone`의 한계
함수·DOM·클래스 인스턴스는 안 된다. 스토어 상태처럼 순수 데이터일 때만 `cloneDeep` 대체.

- 6. 점검 루틴 5단계
`npm ls --omit=dev --depth=0` → Bundlephobia / 번들 분석기 → webstatus.dev → 질문 3개 → 필요 시 기능 감지 뒤에 교체. 분기마다 한 번.

> **📌 결론**
> ▎ 라이브러리가 남아 있는 건 게을러서가 아니라 다시 안 들여다봐서다
> ▎ 국제화(`Intl`), HTTP(`fetch`), UI(`<dialog>`/Popover/앵커), Lodash 일부가 대표 교체 대상 — 합쳐서 gzip 60~90KB
> ▎ `fetch` 인터셉터·업로드 진행률, `debounce`, Temporal 폴리필처럼 **남겨야 하는 경우도 분명히 있다**
> ▎ 판단 기준은 "베이스라인인가"가 아니라 "내 사용자에게 안전하고, 싸고, 충분한가"
> ▎ ⭐️ 실무 적용 포인트: 이번 분기에 `package.json` 열어서 국제화 묶음(`timeago`, `numeral` 류)과 `lodash.clonedeep`/`groupby`부터 확인 — 제일 적은 리스크로 바로 줄일 수 있는 구간
